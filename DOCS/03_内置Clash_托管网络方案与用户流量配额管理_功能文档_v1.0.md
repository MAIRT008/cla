**用户主流程**：取得已分配方案 → 查看推荐及影响 → 启用或切换 → 自动验证 → 日常使用 → 查看用量与异常 → 按条件恢复。

## 1. 产品目标、边界与文档衔接

### 1.1 目标

把网络配置的技术工作集中到管理后台，使普通用户不必理解订阅 URL、前置代理、固定出口、TUN、DNS 或规则语法。用户主要操作是选择方案、启用或切换、查看状态和流量，日常直连白名单是明确开放的自助配置入口。

本板块既支持首次搭建，也支持正常运行中的方案管理。FD-02 发现问题后可以直接调用同一套能力处理，不要求用户在检测页、代理页和外部 Clash 之间搬运报告或手工重复操作。[U1—U4；FD02 §5]

### 1.2 包含与不包含

| 范围 | 本份规定 |
|---|---|
| 应用内置 Clash | 包含运行状态、方案应用、规则和订阅更新、复查与恢复；不依赖外部 Clash 窗口 |
| 管理后台 | 包含模板、订阅、前置代理、出口、用户分配、额度、发布和状态管理 |
| 三套网络方案 | 日常单 IP、Claude 专用单 IP、Claude 专用双 IP |
| 用户直连白名单 | 日常模式中允许用户管理；专用模式保存但不启用 |
| 月度代理流量配额 | 按应用用户计量、汇总、提示、限额和恢复；不是仅客户端显示 |
| FD-02 的检测与处理 | 共享受管配置、执行能力和复查；不重新建立另一套评分或修复入口 |
| 文件、Cookie、账号资料清理 | 继续归 FD-01；切换网络方案不附带清理登录或项目资料 |
| 常驻流量分析与长期行为报告 | 本份规定额度所需计量与状态；完整流量监测板块另行定义 |
| 多设备与虚拟环境 | 对已支持环境标注作用范围；若允许同一用户多端使用则合并额度，不在此确定设备数或虚拟化产品 |
| 商城、支付、复杂计费与多级代理商 | 不因加入额度管理而自动扩展到第一版 |
| 自动识别账号风控、伪装身份、解封 | 不建设；本产品账号与 Claude 账号分开，不以切换方案保证解封 |

这里的管理后台负责资源与配置托管，必须对接服务端计量及限额能力，但不强制管理后台本身转发用户流量。实际线路是否需要新增受管接入节点，由供应商能力验证决定。

### 1.3 本份对既有表达的限定与补充

| 既有表达或位置 | 本份增量规定 |
|---|---|
| 早期讨论让普通用户导入订阅、填写代理、组合线路 | 从普通用户主流程移除；由我们在后台配置和分配 |
| FD-02 §5.2 提到用户高级规则编辑 | 托管方案下不默认开放任意规则／YAML 编辑；第一版明确开放日常直连白名单，其他受管设置由后台维护 |
| FD-02 §3、§8 的确认后执行 | 单次诊断处理仍按确认执行；新增首次启用时对自动维护的范围授权，范围内常规更新不反复弹窗 |
| 早期“后台只发布配置” | 增加对实际代理服务的用户计量、额度和停用能力接入；不能只靠客户端计数限制用量 |
| 固定出口与不得静默回落 | 继续有效，并明确适用于额度耗尽、更新失败、方案切换和资源异常 |

上述为本轮明确的局部修订，不修改 FD-01／FD-02 原文件。项目保护、无聊天框、用户确认账号状态、诊断证据与实际复查要求继续有效；不得将自动维护授权扩展成任意文件清理或系统改动。[FD01 §2—3、§6；FD02 §2、§5、§8]

## 3. 三套预设网络方案

### 3.1 方案矩阵

| 方案 | Claude 流量 | 其他普通公网流量 | 国内公网直连 | 推荐用户 |
|---|---|---|---|---|
| 日常模式：单固定 IP | 固定出口 A | 未命中直连白名单的流量走 A | 仅批准的白名单目标直连 | Claude 免费用户 |
| Claude 专用：单固定 IP | TUN 接管，固定出口 A | TUN 接管，固定出口 A | 默认不启用日常白名单 | Pro、Max 5x |
| Claude 专用：双固定 IP | TUN 接管，Claude 专用出口 A | TUN 接管，日常出口 B | 默认不启用日常白名单 | Max 20x |

推荐对象沿用本轮用户要求；前台是否显示某方案、能否启用，以后台实际分配与资源就绪为准。不能仅凭用户选择了某种 Claude 套餐，就宣称其账号风险高低或资源已经开通。

### 3.2 单 IP 与双 IP 的准确含义

单 IP 指应走托管代理的业务流量共用一个固定出口。日常模式仍有白名单直连；Claude 专用单 IP 则默认让普通公网业务统一通过 TUN 走固定出口 A。

双 IP 指同一用户使用两个分工明确的最终出口：Claude 走 A，其他普通公网流量走 B。它不表示随机轮换、自动借用其他用户出口，也不表示每条线路分别获得一份完整月流量额度。

固定出口不自动等于独享出口。后台必须单独记录实际资源是否共享或独享，前台只能按已分配资源说明；本份没有承诺所有用户都获得独享 IP。

### 3.3 TUN、直连与基础通信

TUN 是方案的流量接管方式，不与“日常分流”构成互斥关系。日常模式底层是否使用 TUN，留待技术验证；不能把“日常模式”写死为关闭 TUN 后仅依赖系统代理。

本机回环、已批准的局域网通信，以及建立前置代理与固定出口链路所必需的基础通信，由模板定义必要范围。这些不是普通公网业务的任意直连通道。具体 DNS、控制通信、局域网和连接建立例外，必须在配置与验收时明确，不在此补写未知地址清单。

“统一走固定出口”指方案覆盖的业务连接遵守路由，不表示无需建立到底层代理服务的连接。客户端、浏览器、WSL 等具体覆盖范围要声明并验证；没有验证到的对象不能被概括成全机已受保护。

### 3.4 不同“模式”分开表达

本节三套是网络方案；FD-01／FD-02 的标准模式与 AI 增强模式是诊断方式，二者不互相替代。用户不需要在首页面对六种组合，网络方案卡片与 AI 状态分别展示即可。

## 4. 后台托管与按用户资源分配

### 4.1 后台管理职责

| 管理对象 | 功能要求 |
|---|---|
| 方案模板 | 维护三套方案的路由、DNS、保护、必要直连范围及版本，不让每个用户自行拼配置 |
| 机场订阅 | 后台配置订阅来源、刷新状态和可用资源；不将完整共享订阅默认下发给所有用户 |
| 前置代理 | 为到达固定出口选择已批准的前置资源，记录其与最终出口的关系 |
| 固定出口 A／B | 记录实际地址、连接参数、角色、资源属性和有效期；双出口分工明确 |
| 用户分配 | 为具体应用用户分配可用方案、资源、额度与有效状态；缺资源时不显示可立即启用 |
| 发布与恢复 | 保存配置版本、发布结果、客户端应用状态及可恢复版本 |
| 用量与服务状态 | 对接用户用量、额度、周期、暂停与恢复，区分用户限额和上游资源问题 |

后台用户标识属于本应用，与 Claude 账号标识分开。用户绑定或登录本应用的具体方式尚未选择；本版不引入 Claude 账号池或读取其认证资料的流程。

### 4.2 每用户分配记录

至少记录：应用用户标识、已分配网络方案、订阅或资源引用、前置代理、出口 A／B 及角色、资源共享／独享属性、有效期、额度与周期、服务状态、配置版本和客户端最近应用状态。

日常直连白名单作为用户可编辑部分，与后台保护规则和模板分开保存。模板升级不能覆盖用户清单；用户清单也不能修改后台保护边界。

### 4.3 管理后台与实际传输路径

建议的职责关系沿用已确认讨论：管理后台负责资源分配、发布、额度与状态；客户端内置 Clash 依据分配结果建立实际连接。后台不因提供管理界面就必须处于每条用户请求的转发路径。

但新增月流量限制后，所有交付给用户的可用代理路径都必须纳入服务端配额控制。可复用供应商的用户／子账号计量与限额接口；不满足时才评估受管接入节点，不先把方案扩成通用网关平台。

### 4.4 资源隔离与分配边界

客户端只取得本用户所需的配置或凭据，不获得其他用户的出口或后台全部资源。真实订阅 URL、代理密码和固定出口凭据不进入公开仓库、普通报告或模型输入。

开源代码与托管资源分开：开源不代表公开可使用的网络凭据。具体密钥存储、配置分发和权限实现待技术设计，不能承诺仅靠隐藏客户端界面即可实现资源保密或防止配额绕过。

## 5. 路由规则与用户直连白名单

### 5.1 日常模式的规则语义

日常模式采用“直连许可清单”，不是“访问许可清单”。只允许清单内的普通目标直连；未命中的目标不是禁止访问，而是继续走用户固定出口 A。

不默认添加“所有国内网站／所有国内 IP 直连”的宽泛兜底。Claude 的受保护连接不能因为命中用户域名条目而从固定出口变为直连。

| 流量类别 | 日常单 IP | Claude 专用单 IP | Claude 专用双 IP |
|---|---|---|---|
| 受保护的 Claude 连接 | A；不受普通直连白名单放行 | A | A |
| 命中日常白名单的其他公网连接 | 按已确认范围直连 | 白名单停用，走 A | 白名单停用，走 B |
| 未命中白名单的其他公网连接 | A | A | B |
| 本机、批准的局域网与必要基础通信 | 按模板明确的范围处理 | 按模板明确的范围处理 | 按模板明确的范围处理 |

### 5.2 开放给用户的白名单功能

提供添加、删除、启停和恢复默认清单。用户输入网址后，应用整理为域名规则，并明确展示“仅此域名”还是“包含子域名”，不要求用户写 YAML。

修改前展示影响，修改后回读实际规则，必要时复查路径。范围过大或与 Claude 保护规则冲突时，解释原因与实际生效结果，不能因保存成功就显示全部目标已经获准直连。

此白名单用于网络路由，不是以网页路径、Cookie 或账号为单位的访问控制；具体域名格式、匹配能力和默认条目需要在支持矩阵中明确。

### 5.3 方案切换与白名单保存

切入任一 Claude 专用模式时，日常白名单暂不生效，但用户原有条目保留。界面显示“当前方案未启用此清单”，允许查看；再次切回日常模式按当前有效清单恢复，不要求重录。

后台规则更新应保留用户部分并重新检查优先级。恢复默认或删除用户条目属于用户明确操作，不由后台普通订阅刷新暗中执行。

### 5.4 Claude 保护与本机适配

模板需要覆盖实际支持的 Claude Web 登录与使用连接、Desktop、Code 及必要子进程。浏览器与其他应用共用进程、不同安装路径、Windows／WSL 网络差异等，不通过固定个人路径硬编码解决。

精确应用识别、域名范围与不同环境接管方式留待技术验证；发现实际覆盖不足时交给 FD-02 检查并说明，不将配置模板存在等同于所有客户端均已验证。[FD02 §4.6、§5]

## 6. 用户启用、方案切换与日常运行

### 6.1 首次启用流程

1. 客户端取得本应用用户已分配的方案与资源，显示就绪、未分配或暂不可用状态。
2. 展示推荐方案、Claude 出口角色、日常直连规则、流量额度及必要影响说明。
3. 用户选择方案，确认启用及约定范围内的自动维护，不填写网络技术参数。
4. 应用准备受管配置，检查内核与本机接管条件；涉及系统权限时按实际操作提示。
5. 应用配置后回读内核和相关设置，调用 FD-02 对相应环境与路径复查。
6. 验证满足方案要求后显示“已启用”；否则显示具体未完成项并保留恢复入口。

外部代理实例冲突、权限不足或资源缺失时，不自动强停用户其他软件、不把错误配置强行应用，也不要求用户通过手写规则来完成普通开通。[FD02 §4.6、§5.2]

### 6.2 切换时保持 Claude 出口 A

日常 A → Claude 单 IP A → Claude 双 IP A／B，均尽量保持 Claude 的最终出口 A。变化主要是普通流量是否直连、是否使用 B，以及相应接管和保护方式。

双 IP 切回单 IP 时说明“其他代理流量将与 Claude 共用出口”；若后台资源条件导致必须改变 A，应转为明确的出口变更流程，不伪装成无影响切换。

切换过程固定为：检查目标资源与授权 → 展示影响 → 应用配置 → 回读运行态 → 复测目标路径 → 确认成功。更新页面标签不算切换完成。

### 6.3 运行中连接与切换失败

涉及现有连接重建或短暂断网时提前说明。旧连接如何收尾、是否等待工作结束、具体等待时限由实现验证；本份不宣称每次切换都无感或所有长连接均可保留。

切换失败时，保留或恢复此前仍有效、仍获授权的方案。无法恢复则说明失败并保持相应保护，不自动启用未知节点或放开公网直连。

### 6.4 界面关闭、内核与保护状态

关闭窗口、停止代理内核、解除网络保护是不同操作，名称与实际效果必须一致。日常页面展示已连接、线路异常、保护阻断、等待处理等用户可理解的状态。

托盘、后台常驻、开机启动、重启与卸载的具体建议默认值见 [运行行为](RUNTIME_BEHAVIOR.md)，属于待评审的实施提案；产品首次启用应说明并取得对应范围授权。代理运行和恢复不得依赖 AI 在线。

## 7. 月度代理流量计量与限额

### 7.1 配额对象与口径

后台按应用用户配置月度上限，250 GB 为示例值。普通界面统一显示总额、已用、剩余、下一次重置时间与最近同步时间；具体 GB／GiB 单位和重置周期必须在接入计量后明确，不能混用。

| 计量项目 | 第一版规则 |
|---|---|
| 计入额度 | 经分配的托管代理服务实际传输的上传量＋下载量 |
| 不计入额度 | 日常白名单中真正直连的流量，以及本机／局域网通信 |
| 双固定出口 | A、B 合并计入该应用用户的总额度，不默认每个出口各有一份额度 |
| 多设备／多环境 | 若允许使用，同一用户统一汇总，不按设备重新赠送一份额度 |
| 前置代理＋固定出口 | 选定明确计量点，同一份传输不因经过两段链路重复向用户扣量 |
| 模式切换／重启／重装 | 服务端用量连续保留，不重置、不依赖客户端缓存记账 |
| 周期重置 | 由后台／服务端定义并执行，前台展示时间，不由本机时间决定 |
| 展开明细 | 可查看 A／B 或对应用途的分项用量，分项与总量保持一致 |

是否有具体协议开销、失败连接等字节进入上游计量，须在供应商和计量点选定后公布口径；不能把用户展示量直接等同所有上游供应商各自的计费量。

### 7.2 服务端是额度执行依据

客户端实时流量统计用于显示和辅助核对，不能作为唯一配额依据。后台必须对接可控服务端或上游的用户用量、额度设置、暂停与恢复能力。

所有实际下发的可用接入路径都应纳入同一用户额度，不能其中一条可以绕过限制。供应商只有共享总订阅而没有按用户控制能力时，不具备本版承诺的每用户硬限额条件；需要更换接入能力或补齐受管计量点后再交付。

不规定某一供应商或自建完整代理面板。优先复用现成用户／子账号与配额能力；接口和实际行为验证是接入条件，不是已完成事实。[U3—U4]

### 7.3 同步、周期与一致性

前台用量必须附最近同步时间；同步延迟或失败时保留最后已知值并标记，不用零用量替代未知。到期、暂停、周期重置及后台调额应反映到用户状态。

同一周期内重复上报、切换设备、恢复本地配置不能重复扣量或清空累计量。后台调整额度与周期需记录变更，不把普通配置更新当作新开周期。

月初重置还是开通日起算、时区、告警阈值、统计间隔、计量精度与容许误差未锁定。实现硬限额前应明确达到上限时对新连接和正在传输连接的处理及生效时延，不能先承诺字节级即时截断再补实现。

### 7.4 给用户的简化展示

> 本月代理流量：已用／总额
>
> 剩余额度：按最新服务端结果显示
>
> 下一次重置：显示具体时间与所用时区
>
> 最近同步：显示时间；同步异常时明确提示
>
> 【查看用量明细】　【查看当前方案】

此为字段示意，不填造实际用户用量。双 IP 分项位于详情，普通页面不要求用户理解两个独立账本。

## 8. 额度耗尽、服务异常与恢复

### 8.1 限额状态与用户提醒

接近额度上限时提前提醒，具体阈值待定。达到上限后，由服务端暂停对应托管代理服务，客户端同步显示原因，不把暂停包装成一般网络故障。

额度耗尽不等于关闭 TUN、不等于解除保护，也不等于允许代理流量改用本地网络。客户端停止计量上报、重装或修改本机时间，都不能恢复服务端额度。

### 8.2 各方案在额度耗尽后的行为

| 当前方案 | 额度耗尽后 | 必须保持的边界 |
|---|---|---|
| 日常单 IP | 需要代理的流量停止；已经批准的普通直连白名单仍可使用 | Claude 不因额度耗尽改为直连；未命中白名单的业务不被放行 |
| Claude 专用单 IP | 对应代理业务停止，保留必要本机通信 | 不自动启用日常白名单、不自动降级日常模式 |
| Claude 专用双 IP | A、B 按同一用户总额度控制，代理业务暂停 | 不通过另一出口继续绕过额度，不借用其他用户资源 |

必要基础通信仍受模板范围约束，不能为了显示额度或恢复连接临时新增宽泛直连规则。具体控制服务的可达路径在实施前明确。

### 8.3 不同异常分开归因

| 异常 | 说明与处理方向 |
|---|---|
| 用户额度耗尽 | 显示已用／上限、下一重置时间；等待周期重置或后台调整 |
| 用户服务到期／暂停 | 显示已知服务状态；不能用旧缓存配置继续绕过服务端授权 |
| 上游共享资源先耗尽 | 用户可能尚未用完自己的额度，属于我们需处理的资源问题，不归咎为用户超额 |
| 线路或固定出口不可用 | 显示线路异常及保护状态，不随机换路 |
| 用量同步失败 | 显示最后已知用量与同步缺口，不宣称额度为零或无限 |
| 后台管理服务不可达 | 可以沿用仍有效、已授权的本地配置；服务端配额、到期与暂停继续生效 |
| 配置更新或切换失败 | 恢复适用的旧配置，报告实际结果，不以解除保护隐藏失败 |

### 8.4 恢复条件

周期重置、后台增加额度或恢复授权后，优先继续使用原来分配的 A／B。恢复额度不授权改变固定出口，恢复配置不授权重置用量。

恢复后回读服务状态和线路，必要时触发 FD-02 复查。无法重新获得原线路时如实显示等待外部条件，不声称已经回到此前完全相同的环境。

## 9. 自动更新、发布与配置恢复

### 9.1 自动维护的授权范围

首次启用方案时，一次性说明自动维护覆盖哪些内容并取得授权。以后范围内的常规订阅与规则更新自动完成，不反复要求用户确认技术细节。

| 更新内容 | 处理规则 |
|---|---|
| 订阅列表、域名和规则集合 | 自动获取、验证并按授权应用；不能覆盖用户白名单或突破保护边界 |
| 已批准的前置资源维护 | 可按已选方案维护或选择批准范围内资源；最终出口 A 的绑定与路径要求不随之改变 |
| 变更 Claude 最终 IP、地区或保护范围 | 不属于普通刷新；无明确预授权时须告知并确认 |
| 需要重启或短暂断网 | 自动取得与验证更新，在合适维护时机应用；影响与时机规则需明确 |
| 核心程序／内核升级 | 本版规定受控更新、验证和恢复原则；具体版本、打包、升级策略另行选择 |
| 更新失败 | 保留或恢复此前仍有效的配置，记录失败原因与用户可见状态 |

常规更新授权不是后台任意运行系统脚本、清理文件、停用用户其他软件或更改账号的授权。[FD01 §2—3；FD02 §8]

### 9.2 发布与应用顺序

新版本获取 → 校验配置与资源 → 检查本地适配和保护约束 → 应用 → 回读内核运行状态 → 复查对应路径 → 记录版本与结果。

后台发布成功与客户端应用成功分别记录。下载成功、配置语法正确、内核加载成功、实际路径正确是不同阶段，不能统一显示“更新成功”而省略缺口。

### 9.3 失败恢复与离线行为

应用前记录本次要改变的配置、授权范围与可恢复对象。恢复只针对本次操作，不能覆盖不相关的新修改。旧版本已经到期、被撤销或资源失效时，不通过回滚继续绕过限制。

后台短时离线时可继续使用本地最后有效配置；前提是对应网络资源与服务端授权仍可用。没有有效配置时显示未就绪，不自动使用公共订阅或未知节点。

本地回滚不能回滚服务端流量账目，也不能复活已撤销的凭据。用户白名单、已批准出口绑定、配额和有效期分别保持正确边界。

### 9.4 与单次诊断处理衔接

FD-02 的一键修复仍基于用户确认的具体问题与动作。它调用本模块同一受管配置入口，而不是另写一份覆盖后台模板的配置。

属于常规维护授权内的动作按本节执行；超出授权、改变 A 或保护边界的动作重新说明与确认。应用记录是“后台常规更新”“用户方案切换”还是“用户确认的问题修复”，便于复查和恢复。

## 10. 界面、AI 与信息边界

### 10.1 用户端页面

| 页面或区域 | 必须呈现 |
|---|---|
| 网络方案首页 | 当前方案、可用方案、推荐对象、连接／保护状态、固定出口角色、切换与体检入口 |
| 方案确认卡片 | 与当前方案的差异、直连变化、出口 A 是否变化、潜在短暂断网及自动维护授权 |
| 日常直连网站 | 添加、删除、启停、恢复默认；显示域名范围和当前方案下是否生效 |
| 流量额度 | 本月总额、已用、剩余、重置时间、最近同步；A／B 明细按需展开 |
| 更新与恢复 | 当前版本、最近更新、应用或复查状态、可恢复内容和限制 |
| 异常提示 | 区分额度、到期、资源、线路、配置、后台与同步问题，提供具体可行入口 |

普通用户不操作订阅 URL、代理密码、节点组合或原始规则。尚未分配或不具备资源的方案不能伪装成一键可用；可以显示未开通原因，具体开通业务流程不在本版锁定。

### 10.2 后台页面

后台提供方案模板、订阅与前置资源、A／B 出口、用户分配、额度与周期、发布版本及运行反馈等管理入口。管理员可以维护资源与调整额度，用户只能修改其获开放的清单或选择获分配方案。

本版不扩展充值商城、复杂账单、代理商层级或销售体系。控制需要的用量与资源状态不等于采集用户浏览内容，完整访问行为分析另由后续流量监测需求定义。

### 10.3 标准能力与 AI 增强

| 环节 | 程序必须独立完成 | AI 可辅助的部分 |
|---|---|---|
| 方案获取与分配 | 读取授权、资源和配置版本 | 解释配置冲突或缺失 |
| 路由与保护 | 应用预设规则、执行固定出口约束 | 只读分析异常，不决定临场换路 |
| 用量与限额 | 服务端计量、额度控制与客户端展示 | 解释用量异常，不计算或改写权威账目 |
| 更新与恢复 | 按范围授权执行、复查、恢复 | 分析失败原因、提出受支持建议 |
| 用户交互 | 方案卡片、按钮、结果与提示 | 无对话框，不需要用户通过聊天完成配置 |

AI 不可用时，既有网络、额度控制、更新执行与恢复不失效。AI 不持有任意管理员终端，不接收 Claude 认证资料、代理秘密或用户对话全文。[FD01 §7；FD02 §6]

### 10.4 日志、报告与开源边界

至少记录用户／环境引用、方案、配置版本、授权来源、A／B 角色、应用结果、复查时间、用量来源与同步状态、限额或服务状态，以及更新／恢复结果。公开或用户导出默认脱敏，不包含代理密码、完整秘密订阅、私钥或其他用户资源。

运行状态采集和配置分发所需的数据范围应在实际接入时说明。本份没有授权收集 Claude 密码、OAuth Token、Cookie 明文或对话正文。

### 14.2 交付前必须验证的条件

供应商或受管服务必须能够按用户计量并执行额度，双出口与允许的多端都在控制范围内；否则不能宣称已实现每用户 250 GB 硬限制。

三套方案必须在声明支持的客户端和环境中验证实际流量路径、白名单行为、切换结果、固定出口故障及超额阻断。只提供界面、配置文件或客户端计数不算完成。

具体数值指标在实现前补齐，功能验收按第 12 节执行。未支持范围、同步缺口、资源异常、恢复限制和未通过的验证始终对用户可见。

### 14.3 本板块完成定义

在已声明支持的范围内，管理员可以按用户分配并维护订阅、前置代理、A／B 固定出口、方案和月度额度；普通用户无需网络参数知识即可启用、切换和查看状态，日常直连白名单按许可范围生效。应用在授权内自动维护，变化有记录，失败可按范围恢复；用户用量由服务端统一计量并受限额控制，超额或故障不引发未批准直连或出口变更。

**本板块最终承诺的是：方案由我们做好，资源按用户分配，配置自动维护，用量真实计量，额度由服务端控制；用户只选方案，应用正确执行、验证并按范围恢复。不是把复杂配置换个界面交回用户，也不是以隐藏客户端按钮代替真正的服务端管理。**


## v1.2 实施衔接

共享订阅是资源池，用户配额是独立服务身份下的账目。只停订阅更新不能阻止已缓存配置；必须在服务节点独立停止超额用户的新连接及在途流量，其他用户继续。FD-03/F29—F36 的两种现成接入路径与验收见 [完整方案](V1_PLAN.md)。Claude 固定 A 故障保持阻断；手动应急入口有独立、显式授权范围，见 [运行行为](RUNTIME_BEHAVIOR.md)。

原文中尚未定数值的项目，本轮已在 [待定决策](OPEN_DECISIONS.md) 提出具体默认值和验证任务；它们为建议，不冒充 Owner 已批准或实测通过。原验收 A 编号继续有效，新增跨模块 X 场景见 [综合验收](ACCEPTANCE.md)。
