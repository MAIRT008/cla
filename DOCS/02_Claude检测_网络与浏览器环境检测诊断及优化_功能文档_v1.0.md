## 1. 产品目标与适用边界

### 1.1 目标

让不熟悉 IP、DNS、WebRTC、代理规则和系统配置的普通用户，也能在同一个应用中完成「发现问题—看懂建议—确认处理—验证结果」。不要求用户先读教程、手写 YAML、操作命令行或跳转外部 Clash 客户端。

本份覆盖出口质量、路径一致性、浏览器可见环境、Claude 连接以及本机配置配合。目的在于优化实际使用环境，减少错误配置、未经批准的绕行、连接故障等可控问题；不将评分解释为账号封禁概率，也不承诺通过修改环境解除服务端限制。

### 1.2 文档与模块编号

FD-01 将「Claude 检测」分为本地文件与网络两个板块；后续讨论按交付顺序称本份为「第二模块」。本文件沿用这一称呼，负责网络与浏览器环境板块，不另建一套与第一份相冲突的上层架构。[FD01 §1；U]

### 1.3 包含与不包含

| 范围 | 本份规定 |
|---|---|
| 出口 IP、网络归属、信誉标签与来源 | 纳入检查、分项解释和处理建议；外部情报与本机测量分开 |
| HTTP／IPv4／IPv6、DNS、WebRTC 与路径一致性 | 纳入当前授权范围内的实际探测；覆盖缺口明确呈现 |
| 浏览器环境、指纹、时区、语言与配置一致性 | 纳入检测与诊断；原始特征不直接等于故障或账号风险 |
| Claude Web、Desktop、Code 的连接和有效网络配置 | 按实际客户端及运行环境分别记录，不以本应用自身联网结果代替 |
| 内置 Clash、系统代理、TUN、DNS、规则与受支持保护设置 | 纳入读取、诊断和用户确认后的应用内处理；核心版本与具体接线待技术选型 |
| 处理前记录、变更预览、复查和恢复 | 属于本模块闭环，不是只有检测报告或外部教程 |
| Cookie 值、站点缓存、账号资料清理 | 由 FD-01 处理；本份可检查 Cookie 功能开关等可用性，不重复清理 |
| Windows／WSL／已存在的可访问虚拟环境 | 分环境检测与作用范围标记；不在本份决定虚拟化产品或新建整套虚拟环境 |
| 持续巡检、长期流量分析 | 本份可读取相关记录并保存本次结果；完整常驻监测另由流量监测功能定义 |
| IP 排行榜、广告、社媒／电商／邮件业务评分 | 不纳入核心产品范围 |
| 账号风控自动判断、解封、支付或手机号风险判断 | 不建设；账号正常或受限仍由用户确认 |
| 默认改写指纹、删除系统字体、关闭大量网站功能 | 不作为一键优化方案；不以追求第三方页面零分代替实际环境目标 |

未知或尚不支持的系统、浏览器、配置格式和检查能力，应显示「未完成／不支持」，不能因为功能清单覆盖就宣称全部已实现。

## 2. 已确定的核心产品规则

| 编号 | 规则 |
|---|---|
| R01 | 产品是检测、诊断、处理、复查与恢复的一体化应用，不是网页检测站的桌面外壳。 |
| R02 | Clash 内置于本应用；代理状态读取、规则调整、配置应用和结果回读由应用内部能力完成。 |
| R03 | 同一份生效网络配置由一个明确的应用内管理入口维护；不让两个客户端同时写入同一配置。 |
| R04 | 首次提供深度检查，日常默认快速体检，保留专项检查；不要求普通用户先填技术问卷。 |
| R05 | 标准与 AI 增强模式共用界面、测量和执行能力；没有聊天框。 |
| R06 | 普通扫描只读配置，可执行获授权的网络探测；不自动切出口、关 TUN、重启内核或改防火墙。 |
| R07 | 应用负责专业判断和明确推荐，用户决定是否采用；操作影响不能隐藏在「一键优化」中。 |
| R08 | 本机能够处理的受支持问题，确认后直接处理；外部条件不足和仅供参考的项目单独标记。 |
| R09 | 结果绑定实际浏览器、Profile、客户端、运行环境、探测路径与时间；不将 WebView 扫描结果冒充日常浏览器结果。 |
| R10 | 采用一个主要的 100 分环境评分，越高越好；危急、重要、轻度三级问题与证据状态分开。 |
| R11 | 从严检查范围、真实路径、确认依据和通过条件；未观测到不等于安全，也不等于确认故障。 |
| R12 | AI 主导证据关联、补充检查和处理计划，可经本地受限工具调用已确认的修复与复查；程序验证授权、计算分数并执行，不接收模型任意命令。 |
| R13 | 固定出口故障不静默切换到未经批准的节点或直连；AI 不决定临场更换出口。 |
| R14 | 断网保护演练单独授权；演练之后报告原状态恢复情况，不混进普通扫描。 |
| R15 | 原配置先记录，变更范围先展示；用户确认后不临场扩大对象或动作，复查完成后才认定问题解决。 |
| R16 | CleanIP 为产品对标，开源仓库为实现候选；复用代码不等于接受其全部权重、结论或默认修改。 |
| R17 | 网络结果不替代账号状态确认；不根据连通、Cookie 存在或 IP 得分判断账号是否被风控。 |
| R18 | FD-01 的项目记录、记忆、配置保护与正常登录保留规则继续有效，不由网络优化静默绕过。 |

## 3. 扫描方式与普通用户流程

### 3.1 三类扫描

| 类型 | 使用场景 | 功能要求 |
|---|---|---|
| 首次深度扫描 | 初次使用、环境大幅调整后或用户主动检查 | 发现实际环境与客户端，采集六类检查范围，分析关联和覆盖缺口；AI 已配置并获授权时默认进行深度分析 |
| 日常快速体检 | 首次盘点后的日常使用 | 复查关键配置、出口及必要连接，比较新增或变化内容；未复查项目显示上次证据时间 |
| 专项检查 | 只排查某个问题 | 对 IP、泄漏、浏览器、Claude 连接或代理配合等选定范围检查；不将专项通过包装为整体通过 |

首页只突出一个主要扫描按钮，不排列复杂组合。无 AI 时标准扫描仍可运行；AI 不可用时明确提示降级，不把标准报告冒充 AI 完整分析。

### 3.2 主流程

1. 应用发现客户端、浏览器及已有运行环境；展示本次范围和必要探测授权。
2. 用户点击「开始环境体检」或「AI 深度体检」，应用自动执行已授权检查。
3. 程序汇集检测事实；标准规则或 AI 关联分析，生成问题、等级、评分或未完成状态。
4. 用户查看推荐方案；可取消个别项，也可展开具体证据和高级参数。
5. 应用一次性展示拟变更内容、影响对象、备份、重启或短暂断网说明；用户确认。
6. 应用调用内置 Clash 及受支持的本机配置能力处理，不要求用户另开外部工具完成相同操作。
7. 自动复查，显示已解决、未解决、用户保留、等待外部条件，并提供本次可恢复操作。

出现真实歧义时，只问影响判断的简单选择，例如「这是你准备使用的固定出口吗？」。不能把第一次观测到的出口未经确认就当作正确基准，也不要求用户填写技术参数表。

### 3.3 普通扫描与保护演练分离

普通扫描不主动制造断网、不退出工作中的客户端、不改变路由或浏览器设置。网络探测会访问相应服务，应说明用途和范围；不能把「不改文件」等同于「不产生网络请求」。

「验证断网保护」单独入口说明影响环境、演练内容、恢复目标和必要权限。用户确认后才模拟代理、TUN 或指定出口故障。无法实施或恢复时明确记录，不通过放开未知直连来掩盖失败。

## 4. 六类检测功能

### 4.1 出口 IP 与信誉

| 检查内容 | 必须记录或解释 |
|---|---|
| 当前出口与预期出口 | 实际观测 IP、地址族、检查路径、客户端／环境、时间，以及是否符合用户确认的线路 |
| 基础归属 | 数据可得时展示国家／地区、ASN、网络归属与类型；标注来源，不将地域标签等同实际居住地 |
| 网络与信誉标签 | VPN、代理、住宅代理、Tor／Relay、IDC／Hosting、滥用、黑名单等来源标签；未命中与未取得数据分开 |
| 多源差异 | 不同服务的归属、类型或信誉标签不一致时并列呈现，AI 可分析差异，不能自行捏造统一真值 |
| 历史对照 | 本次与历史出口变化及检查时间；没有历史数据就不声称长期稳定 |
| 处理建议 | 区分本机路径问题与外部 IP 情报问题；切换线路以用户已批准且可用的候选为前提 |

对标截图中的「纯净度」「综合可信度」「原生 IP」「IDC」「Human／Bot」等是网站展示口径，不作为本应用已验证的算法或账号判断。外部数据失效时不以零风险代填；不自动把「代理」或「机房」标签认定为本机异常。[C01]

### 4.2 出口一致性与泄漏检查

| 检查内容 | 必须达到的结果边界 |
|---|---|
| HTTP 与 IPv4／IPv6 对比 | 列出各实际探测路径与观测结果，发现差异后结合选定方案判断；不只对比 IP 字符串就断言泄漏 |
| DNS 出口 | 区分本机配置、浏览器设置、代理 DNS 配置与实际观测；未捕获不直接解释为确定泄漏或确定安全 |
| WebRTC／STUN | 记录实际浏览器、使用的测试、返回结果和对比情况；无公网候选不扩大为全场景安全证明 |
| IPv6 | 区分未取得结果、不支持、已配置禁用和实际路径情况；没有探测结果不能自动认定系统已禁用 IPv6 |
| 时区与出口对照 | 展示浏览器、系统、CLI／客体可见值与出口资料是否偏离选定方案；作为配置一致性检查，不推断国籍或账号风控 |
| 路径结论 | 区分已发现不符合预期的绕行、已完成检查未见冲突、未完成和不适用；记录实际覆盖范围 |

检测工具本身遵守当前已批准网络路径。对比测试需要尝试不同路径时，应单独说明，不以「检测真实 IP」为由默认绕开固定出口保护。DNS／WebRTC 无结果时先继续核查，不为刷绿分关闭原有保护。[C03；C06]

### 4.3 浏览器环境与配置一致性

扫描实际使用的浏览器及 Profile，识别其有效代理相关配置、相关扩展／策略、时区、语言、Intl 区域、UA、浏览器／WebView 类型、可见字体及设备特征。Cookie 是否启用等功能状态可以检查；Cookie 内容和站点数据清理由 FD-01 负责。

默认检测操作系统登记的默认浏览器；多 Profile 时让用户选择实际使用项。经确认应用受支持的 Claude 专用设置；无法由桌面准确测量的项目，打开该真实浏览器中的诊断页。本应用自身的内嵌浏览器或 WebView 不是用户日常 Chrome／Edge 等浏览器的替身。不能验证到实际浏览器时标明缺口；需要用户打开诊断页或授权相应只读检查时，用简单入口引导。

保留 CleanIP 截图中的时区、语言、中文字体、厂商字体、浏览器、设备、Intl、偏移、Emoji 等观测项；不把页面的「中国用户特征」权重照搬为账号风险评分。只有可解释的配置冲突或与已选方案的偏离，才能形成相应问题与建议。[C02；C04]

### 4.4 浏览器指纹与隐私检查

| 检查面 | 本模块用途 |
|---|---|
| Canvas、WebGL、Audio | 记录浏览器可见特征、变化和检查来源，辅助分析环境与配置差异 |
| 字体、屏幕、硬件 | 记录可获得的特征；原始详情置于高级区域，不要求用户理解哈希 |
| 浏览器、时区及组合 | 结合实际 Profile、平台和已选环境分析是否存在异常组合或漂移 |
| 结果解释 | 明确页面启发式特征、实际测量与本应用规则的区别；不由单个哈希推断全球唯一性或账号封禁概率 |
| 处理建议 | 优先针对已确认配置问题；不默认随机化身份特征、删系统字体或关闭大量网站功能 |

首次记录可用于以后比较，但不能把初次出现的所有特征自动认证为正常，也不能将正常硬件特征的存在持续扣分。具体隐私配置的处理范围与兼容性，须在受支持的浏览器版本上验证后提供。[C05]

### 4.5 Claude 连通性与 TLS 检查

检查与选定使用方式相关的目标连接，包括截图出现的 claude.ai、api.anthropic.com；分别说明测到了域名解析、连接、TLS 还是更上层的服务结果。记录检查时间、耗时、错误与作用对象，不能把单次成功说成长期稳定。

Web、Desktop、Code 的结果分开呈现。基础端点探测不自动读取账号凭据，不凭一次连通或失败判断封号。账号状态继续沿用 FD-01 的用户确认结果；认证请求若另有需要，必须先明确授权与实际身份，不作为本份自动风控功能。

TLS 版本、ALPN、证书和可得的 JA3／JA4 等放高级诊断。记录由哪个客户端、哪条连接以及哪个观测服务产生；不能用桌面程序自身的 TLS 特征冒充实际浏览器特征。外部服务无返回、数据不足或方法不支持时保留未完成状态。[C03；C07]

### 4.6 内置 Clash 与本机配置配合

| 检查对象 | 功能要求 |
|---|---|
| 应用内置 Clash | 读取内核运行状态、活动配置、模式、代理组、选定出口、DNS／TUN 与受支持的运行数据 |
| 系统代理与 PAC | 识别实际设置与作用范围，不能用客户端环境变量代替系统配置检查 |
| 客户端有效配置 | 读取 Desktop／Code／浏览器在已支持方式下实际使用的代理来源，标记冲突和未知项 |
| 规则命中与连接路径 | 配置存在、配置应用、运行态读取、实际命中、实际出口分层展示，不混作一个通过 |
| 宿主与客体 | Windows、WSL、已存在的可访问虚拟环境分别检查；不把一份全局设置不加区分复制到所有环境 |
| 出口保护 | 静态覆盖检查与单独授权的故障演练结合；内核日志没有直连记录不等于整个客户端没有绕行 |
| 其他代理工具 | 发现外部实例、端口和配置接管冲突；默认只读，不自动停止或卸载用户其他软件 |

Clash 不是本模块列出问题后让用户去操作的外部依赖。受支持的读取、诊断、修改、应用和复查在本应用内完成；本机控制能力、具体内核和版本支持另由实现确定。[U]

## 5. 内置 Clash 的集成与执行边界

### 5.1 一个应用内的完整处理流程

网络检测界面、AI 诊断、内置 Clash 管理和本机配置执行共享同一问题与处理清单。内部可以分职责，但不让用户在模块之间复制报告、手工搬运规则或到另一个 Clash 窗口点击应用。

| 内部职责 | 对用户的结果 |
|---|---|
| 检测与诊断 | 知道哪里有问题、依据是什么、建议怎样处理 |
| 内置 Clash 配置管理 | 直接读取和应用已确认规则、代理组、DNS／TUN 与出口选择 |
| 本机配置执行 | 处理支持的系统、浏览器及客户端设置，明确权限与作用范围 |
| 复查与恢复 | 验证实际运行结果，保留本次变更记录和恢复入口 |

以上为职责划分，不是要求新建多个网关、多个独立控制界面或第二套代理运行链。

### 5.2 唯一生效配置与外部冲突

应用内保存用户选择和受管配置，生成或应用实际运行配置，并回读确认。检测页与代理设置页修改同一套受管状态，不各自写入彼此覆盖的配置副本。

导入既有配置是用户明确授权的操作，不默认执行其中脚本、不默认取得所有配置的所有权。现有外部 Clash 或其他代理工具仍占用控制范围时，应解释冲突并要求明确选择，不能双方同时管理相同生效设置。

用户仍可以在本应用的高级设置中调整规则；调整后通过同一管理入口重新应用和复查。截图、旧方案中的个人节点名、端口、路径和网卡名不是通用硬编码。

### 5.3 固定出口与失败处理

受控环境已选择固定出口时，节点不可用、内核停止、TUN 关闭等情况不得静默回落到其他节点或公网直连。重新选择出口必须属于用户明确批准的方案；AI 不为了提高分数或恢复联网自行换路。

「保护按预期阻断连接」与「线路当前不可用」分别报告。演练期间的预期失败不能计成保护失效；相反，未经批准继续联网才是需要处理的路径问题。

关闭应用界面、停止内核、关闭网络保护分别说明其影响。恢复只能回到用户已确认的原状态或明确支持的恢复目标；恢复失败不能靠解除保护来假装成功。

### 5.4 与第一模块及双环境功能的衔接

同一代理字段或接入配置若在 FD-01 与本份都被发现，应关联为同一问题来源，不重复修改或累计成多个严重问题。涉及项目配置时，默认保护既有项目内容，优先使用受管运行设置；不能因用户点击网络优化就整份重写项目配置。

本份对已存在且可访问的环境检查、应用受支持的网络设置并分别验证。虚拟机类型、环境创建、镜像分发或完整隔离能力不因本份出现「WSL／虚拟环境」就被视为已选型或已实现。

## 6. 标准模式与 AI 增强模式

| 环节 | 标准模式 | AI 增强模式 |
|---|---|---|
| 事实采集 | 程序执行支持的检查并保留证据 | 使用同一采集能力；可请求授权范围内的补充只读检查 |
| 关联分析 | 依据固定规则和已验证案例解释 | 关联出口、DNS、浏览器、客户端、内置 Clash 和历史变化，提出原因与验证建议 |
| 推荐方案 | 由支持的处理规则生成 | 提供更有针对性的建议与理由；不能生成未经支持的任意系统操作 |
| 评分 | 程序按固定版本规则计分 | 同一规则计分；模型不临时决定分值、改权重或将未知补成正常 |
| 执行与恢复 | 用户确认后调用应用内部能力 | 同一执行与恢复层；模型没有任意管理员终端 |
| 复查 | 重新测量并更新状态 | 程序测量，AI 可解释剩余问题；解释不替代证据 |

AI 输入以脱敏结果、有效配置摘要、受支持操作说明和经筛选案例为主。账号凭据、Cookie 值、代理密码、私钥和未授权资料不发送给模型。网页、日志和配置中的文字仅作为分析数据，不成为扩大权限的指令。

可确认事实、推断原因、待核验内容在报告中分开。源数据互相矛盾时，AI 应指出差异并提出下一项检查，不选择一方后伪称已经证实。

AI 故障或外部网络不可用时，标准本机检查、已有结果、内置 Clash 管理与本地恢复仍可运行；联网探测失败如实显示，不把「离线仍可操作」写成「断网时全部检查也能通过」。

## 7. 结果分类、严格评级与评分

### 7.1 一套首页分类

六类检查对应六类结果：出口 IP 与信誉、出口一致性与泄漏、浏览器配置一致性、指纹与隐私、Claude 连通性与 TLS、内置 Clash 与本机配合。正常项默认折叠，优先呈现问题和关键未完成项；高级参数不挤占首页。

### 7.2 检测状态与问题等级分离

| 检测状态 | 表达含义 |
|---|---|
| 正常 | 该项适用检查已经完成，未发现违反选定方案或当前规则的问题 |
| 异常 | 存在有证据支持的问题，随后分危急、重要或轻度 |
| 未完成 | 未授权、未访问到、未观测到、外部服务失败或方法不支持，必须说明原因；可附待核验假设 |
| 不适用 | 已确认该项不适用于本次对象或使用方案，不等于缺结果时随意排除 |

| 问题等级 | 判定原则 | 用户提示 |
|---|---|---|
| 危急 | 已证实严重的路径违反或保护失效等问题，例如受控客户端绕到未经批准的出口；必须指出对象与实际证据 | 建议立即处理 |
| 重要 | 已确认配置冲突、持续连接故障或影响选定环境的明显问题，但未达到危急条件 | 建议优先处理 |
| 轻度 | 不阻断当前使用的明确优化项或轻微异常；不能仅凭硬件、字体或代理标签存在就判问题 | 可以稍后处理 |

严重等级、证据确定程度与操作影响分别记录。待核验不是第四级危险；没有 DNS／STUN 结果既不自动刷绿，也不自动判为已确认泄漏。

### 7.3 100 分框架与待定参数

主评分名称为「Claude 网络与浏览器环境评分」，满分 100，越高越好。其含义是本轮适用检查与所选环境要求的符合情况，不是账号安全保证、国籍特征分或封号概率。

保留以下已确定规则：同一根本问题归并计分；关键检查未完成不发布最终总分；尚有危急问题时不能以其他正常项平均成优良结果；重要问题不能藏在「全面达标」中；用户保留真实问题不会自动清除问题；复查确认解决后才更新分数。

外部 IP 信誉、网站特征指数和本机测量不可直接相加或简单平均。展示原始分时必须附来源、方向与时间。本份不沿用 FD-01 的 40／15／2 扣分、59／84 上限；网络检测的扣分、封顶、延迟阈值及完整度计算须单独确定并版本化。

**本份锁定评分产品框架，不凭空补写算法。** 评分规则发布前必须完成逐项映射和案例校准；演示稿不得将临时数字冒充实测或已认可的规则。

v1.2 已补候选算法与逐类映射，见 [评分与基础路由提案](SCORING_AND_ROUTING.md)；它是实施评审输入，仍须样例校准，不将建议数字标记为实测或 Owner 已批准。

### 7.4 一致性要求

总览、问题列表、详情和处理建议必须引用同一批检测结果。若详情是「IP 一致、时区匹配、DNS 未捕获」，摘要不能直接写成「已确认 IP 或时区冲突」。截图中的此类展示差异用作验收样例，不据此猜测网站内部算法。[C06]

快速体检注明本次复查与历史保留证据，专项检查只说明专项结果。模型切换不应在相同规则与相同已确认问题下随机改变总分。

## 8. 推荐处理、确认执行与恢复

### 8.1 三种处理方式

| 标签 | 意义 | 操作入口 |
|---|---|---|
| 可直接处理 | 已有明确对象、支持的动作和所需权限，用户同意后可在应用内完成 | 加入推荐方案、确认处理 |
| 需补充条件 | 例如缺少替代线路、外部服务或授权；条件补齐后才能执行 | 选择／添加条件、重新检查 |
| 仅供参考或继续核验 | 只是外部情报／特征，或证据不足，暂不能生成可信变更 | 查看依据、继续检查、复测 |

不是每个检测项都必须有「修复」按钮；但对已经支持且条件满足的本机问题，不能只提供教程而不提供执行入口。

### 8.2 处理动作目录

| 已确认问题 | 应用内处理能力 | 处理后验证 |
|---|---|---|
| 客户端代理配置失效或来源冲突 | 修正支持的客户端／受管运行配置，保留无关设置；必要时提示重启 | 回读有效配置并对该客户端复测 |
| 内置 Clash 规则不符合预期 | 展示并应用规则或代理组变更；所有页面使用同一配置入口 | 配置生效、实际规则命中与出口分别检查 |
| DNS 设置与选定方案不一致 | 定位系统、浏览器或内置 Clash 中责任设置后调整 | 复查配置与实际可观测路径，不仅验证文件已保存 |
| IPv6 路径不符合预期 | 应用经过支持验证的路径／保护设置；不默认关闭整机 IPv6 | 验证相应环境及客户端路径，缺测说明 |
| WebRTC 路径不符合预期 | 使用浏览器支持且经过验证的网络策略；不默认安装未知扩展 | 在实际浏览器复测并说明未观测范围 |
| 浏览器／系统／CLI 配置偏离用户方案 | 展示当前值、目标值和系统级影响，确认后调整支持项 | 分环境回读与验证，不伪造身份特征 |
| 受支持的证书／连接配置问题 | 先定位原因，给出支持范围内的配置恢复或调整方案 | 验证受影响连接；不以关闭证书验证消除报错 |
| 固定出口保护配置缺失 | 应用支持的保护设置；故障演练另行授权 | 静态检查与已授权演练结果分开 |
| 现用线路不可用且有替代线路 | 仅按用户确认切到已批准的可用候选 | 验证新出口并更新环境记录；不静默换号或借用其他身份 |
| 外部 IP 标签或服务端异常 | 解释来源与限制；按条件提供线路选择或等待复测 | 不伪称已修改第三方信誉数据库或解除服务限制 |

上表为需求范围，不证明所有系统和版本都支持相同操作。DNS 未捕获不意味着一律启用 DoH；浏览器特征偏离也不意味着一律修改系统语言。先定位问题，再采用明确方案。

### 8.3 执行确认与变更范围

推荐卡片显示问题、依据、严重等级、处理方式、当前值与拟变更、影响范围、是否重启／短暂断网、备份和复查方法。用户可取消或保留，应用不得默默执行剩余之外的动作。

确认后固定具体环境、客户端、Profile、配置项与线路。执行前检查当前状态是否变化；原方案失效时暂停相关操作并刷新说明。AI 不临场追加动作、生成任意脚本、切换未批准的出口或扩大到其他环境。

涉及退出工作中的浏览器或客户端、系统级改动、权限提升和保护演练时，明确说明影响。普通检查不要求整应用常驻管理员权限；实现如何限制系统权限需在技术设计中落实。

### 8.4 备份与恢复

修改前记录本次要改的配置和可恢复范围，秘密字段留在本地受限存储。恢复只针对本次操作，不还原整台电脑、不覆盖无关新修改、不把外部 IP 数据或服务状态列为可恢复对象。

恢复前检查当前状态；与备份后的用户修改冲突时说明差异，不盲目覆盖。恢复完成仍需回读、必要复测，并显示未恢复项。恢复不意味着保证恢复原公网 IP、服务端账号状态或已失效会话。

### 8.5 执行与复查状态

逐项显示：已应用且验证通过、已应用但尚未验证、验证仍异常、按用户选择保留、等待外部条件、未执行、执行失败、已恢复或恢复未完成。

配置写入成功不等于实际问题解决。只有对应检查证据更新后才修正等级与分数；部分成功按部分报告，不将一键操作包装成全部完成。

这是一套可追溯结果字段要求，不意味着现在必须搭建独立数据平台或多层控制系统。具体编码与存储方案后续确定。

### 9.3 报告与隐私

浏览器指纹、详细网络拓扑和代理信息仅在所需范围内采集；外部探测或 AI 服务接收什么应告知用户。授权检测不等于同意把整份本机配置上传第三方。

报告保留当前与历史的区别；外部信息不能被改写为「本应用亲自测得」。账号状态只标注用户确认来源，不输出自动封号判断。

### 14.2 本模块完成定义

在明确声明支持的范围内，普通用户可以一键完成网络与浏览器体检，得到可解释的评分或检查缺口，知道哪些问题危急、重要或轻度，以及哪些可直接处理、需要条件或继续核验。用户确认后，本应用通过内置 Clash 与受支持的本机配置能力执行准确变更，再以真实客户端和环境的复查结果说明是否解决，并提供受限、可追溯的恢复。

最终交付须通过第 11 节适用场景。未完成的检查、未解决问题、外部条件不足和恢复限制始终可见；代码复用与 AI 分析均不能取代实际验收。

**本模块最终承诺的是：检测到对象、诊断有依据、建议可执行、用户同意后在应用内处理、处理后验证并能按范围恢复。不是复刻一个网站，也不是用一个高分保证账号永不受限。**
