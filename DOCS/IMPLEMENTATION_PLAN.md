# 开发计划与工期重估

> v1.3 · 2026-09-12。首轮离线施工已启动；以当前阶段交接证据记进度。Owner 最新授权先做界面和核心功能，实网测试留到另一台指定电脑并逐项获批；未授权改变本机网络、环境、部署或公开发布。

## 当前执行顺序

本轮使用 Owner 选择的 GPT-5.3-Codex-Spark 施工，当前验收 Agent 独立验收与技术裁决；GROK 接入后按文件范围分派独立工作。首轮任务与限制见 [当前施工边界](../evidence/p0/owner-scope.md)。

1. 先完成桌面复用的源码对照、合成数据清理执行器及其真实本地验证；界面外观和前端交互可在桌面集成尚未定型时先行，避免让实网证据阻塞独立部分。
2. 推进四模块界面、本地状态/确认/执行/复查/恢复、离线日志分类与报告等核心功能。涉及外部资源的界面通过明确的演示数据和未接入状态呈现；演示不计作网络、配额或 AI 实测通过。
3. 界面和离线功能形成可操作交付后，准备可搬到另一台电脑的构建产物、配置示例和分项测试操作。真实模型、代理、出口、浏览器诊断、故障保护及用户配额须等待对应资源和明确批准，在批准的机器与范围内验证。

下文 P0—P7 保留完整首版工作与验收要求；涉及实网的依赖推迟到获批测试阶段，不削减功能，也不把尚未执行的项标成完成。当前机器不用于代理核心启动、系统网络变更、连通/出口探测和故障注入。

## 1. 重新估算的结论

当前执行分工由 Owner 指定：**GROK 与 Codex 5.3 共同施工，当前验收 Agent（本任务）负责独立验收和技术裁决**。施工方承担选型试验、实现、自测和整改；验收方按实际证据决定技术取舍、阶段通过或返工。项目当前文档是唯一实施依据，不从 ZIP 副本另起一套。

以下时间仍来自先前单条施工主线的参考估算；改为两名施工 Agent 不自动意味着工期减半。正式开工时按具体分工、可并行部分和实际选型结果更新：

| 交付点 | 从开工起的估计 | 到时实际应能做什么 |
|---|---|---|
| 可运行技术样机 | 原参考约 1—2 周，待对应路线实测校正 | 真实 AI 清理一类合成配置，真实内置代理/固定链，默认浏览器回传，服务端独立停用用户的关键证据；界面未完整 |
| 四模块功能内测 | 原参考约 4—6 周，待选型校正 | 在首批支持矩阵上完成扫描—确认—处理—复查、三方案/配额、监控/日报闭环，可由 Owner 持续试用 |
| 完整 V1 小范围试用 | **原参考 6—8 周，尚未冻结排期** | 安装、启动/退出、恢复、保护故障、真实多人共享额度、基本兼容和 3—5 位用户试用均有结果 |
| 公开发布 | 在试用放行后安排 | 许可证、公开材料、安装包与发布账号检查；不以文档齐备自动发布 |

这里一周按五个有效工作日计算。有效工作日指有持续编码、测试和处理反馈的时间，不是只运行一次模型或每天零散一小时。没有假设新增两位工程师，也不把 AI 生成代码速度等同于外部资源和实机验证速度。

**此前 16—24 周的估算不再作为当前排期依据。** 它把兼容范围、精确应用归属和未知保护/计量工作按较宽生产实现顺序相加，没有充分折算现有 Clash 和归档方案的复用。现在已明确默认浏览器、有限支持矩阵、不追求全应用归属、AI 主导清理及单个现成配额适配，因此按具体任务重算，而非简单对旧数字打折。

6—8 周保留为 v1.2 的参考基线，本轮没有实际集成工时，不另给更短承诺。定型后只重算受影响任务：删除已被复用覆盖的工作，加入实际裁剪、适配和验证工作，外部资源等待单列。供应商原生能力、完整链路和故障保护必须取得证据；不能通过把共享额度降级为客户端自限来满足工期。

## 3. P0：先收口候选，再验证会改变采用决定的路径

先按 [复用计划](REUSE_PLAN.md)收口：供应商原生用户能力优先；桌面只比较 CVR 裁剪与轻壳；AI 只比较现成模型 SDK 加窄工具循环与 Pi。每项记录候选版本、能直接保留的能力、必须改接或新增的部分、维护/许可条件和最小验证。上轮初筛的第一顺位不能作为最终采用决定。

目标不是完整 UI，而是把会改变采用决定的条件测清。桌面对照使用相同的受管配置应用、回读、退出/恢复场景，不能只以能添加页面选定底座。此阶段只使用授权测试资源，不改 Owner 现用网络。

| 任务 | 拟产出位置 | 最小操作与退出条件 |
|---|---|---|
| P0-A 共享订阅用户控制 | evidence/p0/quota-proof.md，fixtures/quota/ | 先核实供应商原生接口；缺口明确才接一个成熟节点。先列协议/凭据/A-B同账方式，用一个用户跑通全链计量；随后三个用户共享资源，耗尽其中一人，验证该人 A/B 新连接/在途停止和缓存不能绕行，另外两人继续 |
| P0-B 固定链与故障保护 | evidence/p0/network-proof.md | 用测试出口验证三模式；A 不可用、内核退出、TUN 失效、UI 退出时测试受保护程序新连接；记录观察/发令/生效三个时间点 |
| P0-C 默认浏览器与应急 | evidence/p0/browser-proof.md | 真实默认 Chrome/Edge 页面回传；所选 Profile 证据。优先用已安装可区分第二浏览器验证应急，缺少时再验证其他明确路径；应急可用且受保护浏览器不改路，仅支持站点可用不算普通应急上网完成 |

输出包含固定版本、实际命令/配置摘要、预期/实测、缺口和采用/放弃理由。首轮时间盒结束即记录结果：已证伪则停止该路线并说明最小替代；证据不足则保留 UNKNOWN，明确下一项必要操作与剩余工作，不把超时当成通过或自动淘汰。无需等待四项全部结束才允许已定型的独立本地工作继续。

P0 的有效样例和适配代码继续接入后续产品，避免验证完后全部重写；临时脚本仍须完成支持范围和保护适配后才能成为用户自动操作。P0 为各路径保存实际采用证据，不新增统一审批平台；全部适用产品验收仍在 P2—P7 完成。

## 4. P1：一个公共底座

逻辑改动位置为桌面、管理后台、内部业务对象、本地保存及网络服务适配。轻壳路线可落在 apps/desktop/、services/control/、internal/contracts/、internal/localstore/、internal/networkservice/；若采用 CVR 则沿其已有目录接入，不为配合此目录表搬迁成熟模块。其余 P2—P7 路径同为职责定位，定型时映射实际仓库路径；当前没有这些产品实现。

只实现首个真实闭环需要的应用登录/模型代理、客户端提示词、范围、对象引用、确认和回执、本地保存、错误与取消。资源管理随 P4 接入，公共能力随第二个真实消费者补充。UI 复用结果卡片和网络入口，不先造完整通用任务框架或第二个 AI 后台。

验证：桌面正常权限启动；未启用网络不修改代理；无模型可标准扫描；模型配置不出现在客户端包和日志；普通用户不能获得其他用户资源。保持最小认证/管理能力，不新增商城、账号池或组织管理。

## 5. P2：AI 清理形成可用闭环

拟创建 internal/discovery/、internal/cleanup/、internal/ai/、apps/desktop/prompts/cleanup.md、tests/cleanup/。

对应 FD-01/F01—F28、A01—A22。依次实现发现范围→用户账号回答→保护对象标签→AI 受限读取/精确计划→批量确认→一次本地批量工具执行（逐项检查、备份、修改、复查）→评分/AI解释→报告和恢复。模型不逐文件驱动确定性步骤，新增动作仍重新确认。

首批格式从历史已确认样例提取，使用合成测试数据：整文件仅第三方状态、混合 JSON 字段、已知数据库选中记录、正常 OAuth、受限账号与项目共存、站点共享数据、不可读/占用/未知格式。模型输入保留用途证据，去掉秘密和真实身份。

验收重点：不是生成一份好看建议，而是至少每个承诺操作类型真实修改成功；保留内容无变化；目标在确认后被改动则暂停；重试不重复删改；恢复冲突可识别。AI 生成新路径/删除命令不可绕过工具范围。

## 6. P3：内置网络和保护

拟创建 internal/network/、internal/networkservice/、internal/emergency/、tests/network/；使用固定 Mihomo 版本与 P0 确认的系统保护实现。

对应 FD-03/F13—F28，FD-04/F09—F20、F22—F24，以及 FD-02 的受管修复交接。先完成下载/验证/应用/回读四状态，再做三模式、用户白名单、升级恢复、后台维护、托盘/启停、应急入口。

验证按网络测试资源执行：A/B最终出口、专用白名单停用、错误配置保持上个有效版本、A故障及核心停止时不走未知出口、应急仅开放批准范围。用户看到发出动作与实测结果区别。复用成熟内核管理，不重新造 Clash GUI。

## 7. P4：共享池与用户配额

拟创建 services/control/allocations/、services/control/quota/、tests/quota/。所选成熟节点/服务商配置保存在部署示例中，秘密由部署环境注入。

对应 FD-03/F01—F12、F29—F36，FD-04/F06—F08。接入 P0 通过的唯一用户计量权威，管理后台维护资源池、用户 A/B、额度/周期和状态；前台显示个人与共享池故障的不同含义。

验证用户甲用完、乙丙可用；甲所有出口与缓存节点均受控；服务端重启、客户端重装、时间修改、换模式、旧配置恢复不重置账目；复用链不重复扣量；新连接/在途停止实测达已评审的目标。没有这组证据就不能把用户硬额度标完成。

## 8. P5：实际网络与默认浏览器

拟创建 internal/diagnostics/、apps/desktop/frontend/diagnostic-page/、tests/diagnostics/。

对应 FD-02/N01—N34、A01—A28。复用采集实现，按六类检测输出来源、实际路径、缺测和分级；默认浏览器/Profile 与本地环境绑定；通过真实页面补测，处理支持的专用设置并复查。

验证 WebView与真实浏览器结果不混用；国内回显未走直连时不称 ISP IP；DNS/IPv6/UDP 的支持与拒绝符合该链能力；同一浏览器共享进程的归属范围可见；不支持设置明确给出人工操作和复查。评分规则采用既有 FD 口径，AI 不临时改权重。

## 9. P6：复用分类、统计和日报

拟创建 internal/monitor/、internal/routeclass/、internal/audit/、apps/desktop/prompts/daily-analysis.md、tests/audit/。

对应 FD-04/F01—F08、F21、F25—F44，与 P3 的保护事件衔接。先复用旧 v2 合成样例，登记产品分类映射；连接字节、服务端配额和日志记录数各保留来源；实现固定窗口/记录去重、双格式交付，再附 AI 分析。

验证跨 09:00、休眠、非 PASS 已交付、报告缺件/损坏、重复快照、时间窗口衔接、错误与覆盖不足并列、原日志含秘密、AI迟到/失败。归档与回放测试不得产生网络请求或修改网络。实时保护在 P3 已实现，此处只接入证据与展示，不重新建设第二套保护器。

## 10. P7：交给普通人使用

拟创建 packaging/、docs-user/、evidence/release/ 与安装/恢复测试。覆盖 FD-03/F37—F40 及各 FD 的导出、降级、兼容场景；完整矩阵见 [验收](ACCEPTANCE.md)。

至少在首批声明的两台不同配置 Windows 测试机上检查安装、扫描、网络启停、更新失败恢复、卸载、断网、休眠、磁盘不足和原代理冲突。小范围试用重点看普通用户能否理解建议/影响并完成操作，不以增加 UI 字段代替易用性。

收口只围绕已承诺功能和直接回归；BLOCK/MAJOR 未关不能放行，MINOR/NOTE 可记录。未支持平台、供应商和格式写入说明，不能标全部通过。

## 11. 进度与验收记录

机器映射见 [任务覆盖](index/implementation-coverage.json)，它维护静态任务归属，不作为运行进度账。实际交接记录按 planned → implemented → verified 更新，并附测试报告/提交引用；首轮实际状态见 [当前施工边界](../evidence/p0/owner-scope.md)，不得用静态 NOT_STARTED 或既有文档 PASS 覆盖实际状态。

原 FD 每个 A 场景均需逐条写 actual_result、evidence、status；同一端到端测试可引用到多条编号，不要求每条另造测试工程。NOT_APPLICABLE 必须依据已评审的支持矩阵，不能用于跳过首版核心承诺。交付不是“写了多少文件”，而是成功标准和真实证据成立。

形成具体采用决定后更新对应任务估时；P2、P4、P7 按实际剩余工作校正即可，不每天重做整套计划。数值候选先记录实测及用户影响，再明确发布目标；不能因为上游默认值不同就直接淘汰或开始改造核心。新增格式差异或供应商限制按实际返工记录，未出现的新风险不持续增加工期。

## 12. 费用与本轮边界

固定出口、上游流量、受管节点/服务器、IP情报/探测、模型调用、代码签名是实际运营成本来源；当前没有采购规格、供应商报价和用户规模，不给虚构月成本。P0记录每用户链路资源与一次扫描/日报实际模型消耗后再估运营成本。

方案和计划文档已完成，首轮项目内离线施工已获授权。测试网络、真实外部服务调用、环境变更和服务器部署仍须按具体操作取得 Owner 批准。本机现用代理及环境必须保持不动；施工进度以实际文件和执行证据为准。
