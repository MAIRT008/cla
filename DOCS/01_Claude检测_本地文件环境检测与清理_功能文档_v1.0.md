## 1. 产品目标与适用边界

### 1.1 目标

让不懂配置文件、浏览器数据库和认证资料的普通用户，也能完成「打开应用—扫描—看懂问题—确认处理—查看复查结果」。用户不需要先学习路径知识，不需要配置对话流程，也不需要逐文件自行判断。

本板块帮助用户优化 Claude 本地使用环境，识别和处理旧登录资料、第三方残留、配置冲突、缓存、日志及旧备份。减少本方可控的残留和错误配置问题，是产品目标；账号风控概率、服务端解封和未来不受限，不属于可承诺的结果。

### 1.2 本份包含与不包含

| 范围 | 本份处理方式 |
|---|---|
| Claude Desktop、Claude Code 的本地配置与数据 | 完整纳入检测、分类、建议和用户确认后的清理 |
| 浏览器中的 Claude 相关站点本地数据 | 纳入各已发现浏览器 Profile 的检测；按站点和具体数据对象处理 |
| CC Switch、第三方 Claude 客户端等关联来源 | 纳入关联识别；不得混称为 Claude 原生缓存 |
| 登录资料、邮箱、accountUuid、organizationUuid／org_id | 纳入本地归属识别；账号是否正常由用户回答 |
| Windows 与可访问的 WSL 数据目录 | 分开识别、标注实际扫描范围；不把宿主检查结果代替客体检查结果 |
| 网络代理变量、接入字段、证书引用等本地配置线索 | 可以读取、分析和按已确认粒度处理；不由此宣称网络路径已验证 |
| 网络连通性、IP／DNS／WebRTC、流量监测 | 不在本份功能中；后续网络板块单独规定 |
| Clash 内核管理、TUN、防火墙与路由改写 | 不在本份功能中；发现关联问题可记录，不自动执行网络修复 |
| 虚拟环境创建、整套环境重建、软件卸载安装 | 不因历史做过而直接加入本份；归后续环境管理范围 |
| 服务端风控探测、内部风险预测、自动解封 | 不建设；不发起探测请求替用户裁定账号状态 |
| 全盘无边界搜索、整个浏览器清空 | 不作为默认扫描或默认清理行为 |

当前路径材料以 Windows 本机为主。其他系统、浏览器和安装方式的实际支持矩阵，需要在实现阶段验证；本文件没有证明全平台已经可用。

### 1.3 决策优先顺序

本轮最后确认的用户规则优先于早期讨论提议；历史台账用于补齐扫描对象、处理粒度和验收样例；社区整理用于补充核查线索。三者不能互相替代。

已撤回的方向不得重新加入：不增加聊天框；不要求普通用户先填写复杂维护目标；不自动判定账号风控；不因旧路径曾被删除就永久判为危险；不为追求高分要求清空所有资料。

## 2. 已确定的核心产品规则

| 编号 | 规则 |
|---|---|
| R01 | 交互参考环境管家式体验：自动扫描、分类展示、明确建议、一次确认、一键处理和复查。 |
| R02 | 首次默认深度扫描；已启用 AI 时进行 AI 深度分析。没有 AI 时仍可运行标准深度扫描。 |
| R03 | 日常默认快速体检，保留手动深度扫描和专项扫描入口。 |
| R04 | 标准模式与 AI 增强模式共用一套界面和执行能力；应用没有对话框。 |
| R05 | 扫描与计划阶段只读；AI 主导识别和处理规划，用户确认具体清单后可调用客户端受限工具执行与复查；任何清理、修改、隔离或恢复须在该确认范围内。 |
| R06 | 应用负责专业判断和推荐，用户负责最终是否采用。不能只列路径让用户自行研究。 |
| R07 | 项目记录、项目记忆、项目配置受保护；其他已识别的 Claude 相关数据可以提供清理选项，但不是全部自动删除。 |
| R08 | 账号状态由用户确认：正常使用则保留对应登录与身份资料；已被限制／风控则把已识别的对应本地资料纳入推荐清理。 |
| R09 | 正常账号的资料存在不扣分；用户声明账号受限也不自动把所有关联文件判为危急。 |
| R10 | 采用 100 分制与危急、重要、轻度三级问题；待核验是证据状态，不是第四个严重等级。 |
| R11 | 从严检查范围、证据和通过条件；不以夸大严重程度、重复扣分或隐藏检查缺口实现“严格”。 |
| R12 | 同一根本问题关联多个文件时归并展示；执行仍保留精确到文件、字段或数据库记录的对象清单。 |
| R13 | 只有执行并复查确认问题解决后才恢复分数；用户保留真实问题不会自动抹除扣分。 |
| R14 | 删除、字段修改、记录清除、隔离保留、原本不存在、执行失败分别记录，不混算。 |

## 3. 数据保留与清理边界

### 3.1 三类项目资料必须按内容保护

| 保留类别 | 保护内容 |
|---|---|
| 项目记录 | 与项目连续性有关的会话记录、工作记录和恢复资料；具体归属由扫描识别，不以文件夹名称一刀切。 |
| 项目记忆 | 项目记忆、连续性资料、项目相关的规则与知识内容。 |
| 项目配置 | 项目设置、使用中的项目规则、项目所依赖的 Skills、hooks、MCP 等配置内容；混合文件中属于项目的部分也应保留。 |

这些资料即使位于用户级目录或全局文件中，仍应按用途保护。例如，不能因为某文件同时含账号信息与项目状态，就将整文件列入账号清理。

无法可靠拆分项目内容与可清理内容时，应保留原对象、显示待核验并继续只读识别；不得以“用户点过一键清理”为由猜测删除。历史中保护过的项目目录与恢复包是保留样例，不是所有机器通用的精确路径表。[S1 §5；S2 unresolved_history]

### 3.2 其余数据“允许清理”的准确含义

在已识别的 Claude 相关范围内，缓存、日志、非项目客户端偏好、旧认证资料、第三方配置、历史备份等可以显示清理或重置选项。推荐与否取决于实际用途、使用状态、用户账号确认和影响说明。

正常账号资料由 R08 特别保护，不因为“其他都可以删”就加入默认推荐。无关软件、其他站点、其他账号和项目内容不自动纳入。

### 3.3 混合与共享对象

| 场景 | 处理要求 |
|---|---|
| 同一 JSON 含登录字段、界面偏好和项目配置 | 展示字段级变更；保留项目内容及未获确认的字段。 |
| 同一数据库含多个站点或账号记录 | 定位具体记录或可明确说明的站点范围；不得删除整个库来冒充定向清理。 |
| 同一对象被多个客户端或环境共享 | 列出共同影响；一个客户端的清理不能静默破坏其他客户端。 |
| 历史备份中含项目资料与旧身份信息 | 先保护项目内容；不能将整个归档默认作为垃圾删除。 |
| 浏览器数据无法精确区分正常账号与受限账号 | 不宣称可仅清一个账号；说明实际可处理范围，未确认影响前不执行。 |

## 4. 扫描方式与用户主流程

### 4.1 三种扫描类型

| 扫描类型 | 默认使用场景 | 扫描行为 |
|---|---|---|
| 首次深度扫描 | 首次使用或用户主动重扫 | 识别客户端、实际目录、浏览器 Profile、账号关联、项目保留内容、第三方与备份关系；AI 增强模式补充内容与关系分析。 |
| 日常快速体检 | 已完成首次盘点后的日常使用 | 复查关键配置和账号关联，重点比较新增或变化内容；不把未复查项冒充本次已验证。 |
| 专项扫描 | 用户只处理某一类资料 | 对缓存、登录资料、第三方残留或旧备份等选定类型进行检查；分数和结果必须注明专项范围。 |

首次已启用 AI 时，主按钮为「开始 AI 深度扫描」；后续默认「开始快速体检」。专项扫描和重新深扫位于次级入口。模式和扫描深度在逻辑上分开，但不排列为六个需要用户理解的首页按钮。

### 4.2 普通用户主流程

1. 打开应用，确认扫描范围与必要的数据使用授权。
2. 点击主扫描按钮；程序自动发现和读取授权范围内的对象。
3. 识别账号后，向用户询问「这个账号目前使用正常吗？」。
4. 标准规则或 AI 分析用途、状态、关联与处理影响，生成评分和问题卡片。
5. 用户查看推荐方案，可以取消推荐项或展开其他可处理内容。
6. 一次性确认具体处理对象与影响，执行清理或修改。
7. 自动复查，展示结果、分数变化、保留项、未完成项及可用恢复操作。

用户不需要先理解“官方 profile”“配置优先级”或其他技术术语。确实影响处理意愿的选择，应在结果中以简单选项解决，不转成聊天对话。

### 4.3 自动扫描的边界

“自动”指授权后按流程完成采集与分析，不意味着首次启动即可上传资料或删除文件。检测过程中不改配置、不停止正在工作的客户端、不清 Cookie、不切网络。

扫描过程支持取消并保留已完成结果；取消或权限不足时显示未完成范围，不发布伪完整报告。AI 不可用时，标准扫描、已有结果和本地恢复能力仍然可用。

## 5. 检测对象与识别粒度

### 5.1 三个主体与关联来源

| 对象 | 扫描内容 | 识别重点 |
|---|---|---|
| Claude Desktop | 实际安装与数据入口、配置、账号关联、登录资料、Local Storage、IndexedDB、Session Storage、缓存、日志、崩溃记录、旧副本 | 当前使用哪套数据；活动配置、历史状态、第三方变体分别标注。 |
| Claude Code | 实际 home／自定义配置目录、用户与项目配置、身份与凭据记录、history、sessions、cache、projects、记忆与规则 | 按用途区分项目资料与运行资料；新生成的正常状态不冒充旧残留。 |
| 浏览器 Claude 站点数据 | 各已发现浏览器、各 Profile 中的 Claude 相关 Cookie、站点存储、缓存、IndexedDB、Service Worker，及实际支持读取的相关记录 | 浏览器、Profile、站点和数据类型同时标注；不只检查默认 Profile。 |
| 第三方来源 | CC Switch 配置／Provider 数据／应用指针、Claude-3p、Claude Nest-3p、reclaude、SAIAI 等实际发现项 | 来源、当前引用关系、是否仍在使用；存在第三方组件不等于恶意或失效。 |
| 启动和系统关联 | Claude 相关启动脚本、环境变量、证书文件及证书引用 | 本份记录配置影响；系统级网络与信任库修改不自动混入文件清理。 |
| 旧归档与备份 | 用户明确范围内的旧环境、配置副本、隔离目录及本应用备份 | 区分活动状态与离线副本，标明项目内容和身份资料；归档不等于已删除。 |

上表是功能扫描范围，不是已实现支持清单。未知格式、无法读取的数据库、锁定对象或未获授权的环境应明确报告。

### 5.2 历史路径仅作为发现线索

必须覆盖本轮材料已出现的路径类型：`.claude.json`、`.claude/`、`%APPDATA%/Claude`、`%LOCALAPPDATA%/Claude`、Claude-3p 相关目录、`Documents/Claude`、`.cc-switch`、`.reclaude`、reclaude 数据目录，以及浏览器各实际 Profile。

扫描时解析当前用户、当前客户端和实际位置，不能把用户历史用户名、节点名、UUID 文件名或某一次版本目录硬编码为通用规则。Windows 与 WSL 的目录结果分别呈现，未访问到一侧就说明覆盖缺口。

### 5.3 每个对象需要识别的信息

至少包括：对象位置、客户端／环境／Profile 来源、文件或内部字段／记录类型、用途、当前使用状态、账号关联、是否含受保护项目资料、证据与不确定性、可用处理动作和影响。

使用状态分为「有证据正在使用」「有证据已停用」「备份／隔离副本」「尚未确认」。不能用“文件存在”替代“正在生效”，也不能仅因文件较旧就判为失效。

### 5.4 关键词与身份关联

邮箱、accountUuid、organizationUuid／org_id 和配置指针可以辅助归属识别。字段直接记录、运行资料中的关联和项目文本中的引用必须区分；关键词命中本身不是登录凭据归属证明。

按指定邮箱或 org_id 扩展检索可放在高级／专项扫描，不要求普通用户知道自己的 org_id。未命中只说明本次已执行方法和范围没有发现目标，不能推断整盘不存在。默认不做无边界全盘读取。

## 6. 账号状态由用户确认

### 6.1 固定交互

识别到本地账号后显示脱敏邮箱或可辨认的本地账号标签，并询问：

> 这个账号目前使用正常吗？
>
> 【正常使用】　【已被限制／风控】

没有聊天框，不自动检测风控，不根据 org_id、Cookie 或 Token 的存在判断账号健康。多个可识别账号分别确认，不用其中一个回答覆盖全部账号。

### 6.2 两条明确分支

| 用户回答 | 推荐清理规则 | 报告说明 |
|---|---|---|
| 正常使用 | 保留对应登录与身份资料；其他缓存、第三方残留和配置问题继续检查 | 「用户确认：正常使用」，不是「系统验证账号无风控」。 |
| 已被限制／风控 | 将明确识别的该账号本地登录资料和相关残留加入推荐方案；用户确认清理后执行 | 「用户确认：账号受限；对应本地资料待清理／已处理」。 |

尚未回答时不替用户推断，暂不清理对应身份资料。无法识别或无法区分归属时按待核验处理；不增加自动探测账号状态的替代流程。

### 6.3 关联清理边界

项目记录、项目记忆和项目配置继续保留。项目中引用受限账号的邮箱或 org_id，不会因此变成可删除的登录资料。其他正常账号资料不自动清除。

混合文件采用可验证的字段级处理；共享浏览器数据先说明实际影响范围。删除本地资料不等于撤销所有服务端会话，更不等于解封；本模块不输出「风控已解除」。

正常账号重新登录后生成的新状态不应被当成历史残留反复清理。账号回答与所识别账号绑定，不能在账号发生变化后静默沿用旧回答。

## 7. 标准模式与 AI 增强模式

| 环节 | 标准模式 | AI 增强模式 |
|---|---|---|
| 采集 | 程序按已支持方式读取资料 | 同一采集能力；必要时请求授权范围内的补充只读检查 |
| 识别 | 版本对应规则、字段解析、明确关联与已验证案例 | 在规则基础上分析内容、引用链、用途、账号归属线索和不一致状态 |
| 建议 | 已验证规则生成处理选项 | 生成针对当前环境的建议和理由；不创造未经支持的删除动作 |
| 评分 | 程序按照固定版本评分规则计算 | 同一评分程序；AI 不随意给出总分或修改扣分权重 |
| 执行 | 用户确认后调用程序能力 | AI 调用同一受限执行工具编排已确认清单并复查，不开放任意管理员终端 |
| 复查 | 程序回读结果 | 程序复查，AI 可解释残留问题；解释不能代替事实验收 |

AI 输入由扫描证据、用户账号回答、识别规则、历史处理样例和补充核查线索组成。AI 的价值是识别到更准确的对象和处理粒度，不是把标准报告润色一遍。

AI 结论区分事实、推断和待核验项。不能因为模型写得肯定就升级为危急；不能把日志、配置或项目文本中的指令当成操作授权。凭据、Cookie 值、代理密码和其他秘密不进入普通模型输入或导出报告。

模型提供方、端点、密钥和模型参数在本应用服务端配置；提示词源与工具说明保存在客户端，调用时随必要脱敏事实发送至本应用服务端。AI 经客户端工具编排识别、获确认清单的执行与复查，不要求用户配置模型 API。具体提供方仍待技术验证，不建设账号池。未授权使用 AI 时不上传；AI 失败时显示降级状态，不将标准结果冒充 AI 完成结果。

## 8. 分类、严格评级与评分

### 8.1 五类结果，来源可筛选

| 界面分类 | 内容 |
|---|---|
| 缓存与日志 | 运行缓存、站点缓存、普通日志和临时验证资料 |
| 登录与账号资料 | 当前及历史身份关联、凭据和站点登录数据，附用户账号回答 |
| 第三方残留与配置问题 | 第三方组件资料、接入配置、失效引用和已证实的配置冲突 |
| 会话与工作资料 | 项目记录、项目记忆、项目配置及其他会话资料；受保护内容明确标记 |
| 旧备份与隔离副本 | 历史配置、旧环境副本及本应用备份；注明是否仍被使用 |

问题按优先级组织，文件路径放在详情中。Desktop、Code、浏览器、第三方来源和运行环境作为标签或筛选项，不强迫用户分头运行多次扫描。

### 8.2 问题严重程度

| 等级 | 判定原则 | 推荐措辞 |
|---|---|---|
| 危急 | 证据充分，当前生效状态存在严重的认证、配置或敏感资料问题；必须说明实际影响，不能只凭路径或身份标识判定 | 「建议立即处理」并展示继续使用的影响 |
| 重要 | 已确认不符合用户选择的环境，存在旧状态、配置冲突或需要处理的敏感残留，但未达到危急程度 | 「建议优先处理」 |
| 轻度 | 主要是冗余、空间或资料整理问题，无证据表明正在影响认证或运行配置 | 「建议整理，可稍后处理」 |

「待核验」是证据状态；关键问题未查清时不能报达标，但也不能把疑点直接升级成已确认危急。正常项目资料和正常账号资料不扣分。

「处理优先级」与「操作影响」分别显示。导致重新登录、清除非项目历史、重置界面偏好或修改接入字段，都需要用人话说明。用户声明风控只是清理建议输入，不是本地危急问题的自动证明。

### 8.3 v1 初始评分规则

评分名称为「Claude 本地文件环境评分」，满分 100。它不是账号安全分，也不是封号概率；网络评分不混入本份。

| 已确认独立问题 | 初始扣分 |
|---|---:|
| 危急 | 每项 40 分 |
| 重要 | 每项 15 分 |
| 轻度 | 每项 2 分，轻度合计最多 10 分 |
| 正常资料或仅提供自愿清理选项 | 0 分 |

计算方式：原始分 = max(0, 100 − 40 × 危急数 − 15 × 重要数 − min(10, 2 × 轻度数))。仍有危急问题时总分最高 59；仍有重要问题时总分最高 84。两种上限同时适用，取更低上限。

同一根本问题的多个文件归并后计一次，不能按文件数堆叠扣分。只有复查确认问题解决后才恢复分数。用户保留实际问题不会自动消除扣分；确认是误报则更正问题与分数，并保留更正说明。

关键检查未完成、关键身份归属未确认或必要范围无法读取时，不给最终总分；展示已发现问题和缺口。专项扫描仅表示专项结果，不伪装成整体环境评分。快速体检保留本次复查范围和历史检查时间，不掩盖旧证据。

100 分表示适用检查已经完成且未发现需扣分的问题，不表示没有任何缓存、没有身份资料或未来不会产生风险。评分数值是本轮讨论的初始参数，须以案例校准；调整时标注规则版本，不能让同一版本随机变化。

>
> 危急 0 项　重要 2 项　轻度 1 项

## 9. 推荐处理、执行与恢复

### 9.1 推荐与决定

应用必须提供有依据的推荐，不仅列路径。推荐方案包含应处理的具体对象、动作、理由和影响；用户可以取消推荐项，也可以查看其他已识别且可处理的内容。

界面主操作为「一键处理推荐项」或「查看推荐方案」。点击后显示一次影响摘要，再由用户确认执行。账号退出、历史清除、接入字段变化等不能藏在普通缓存整理中静默执行。

项目三类资料在本模块内受保护，不把“用户拥有决定权”解释成一键清理可以越过已约定保护范围。

### 9.2 支持的操作粒度

| 操作 | 要求 |
|---|---|
| 删除文件或明确目录 | 已识别用途和范围，保留无关对象；目录内存在项目资料时不能整体删除。 |
| 修改配置字段 | 显示变更字段和保留内容，执行后验证配置仍可读。 |
| 清理数据库记录或站点数据 | 明确实际匹配范围与影响，复查目标和非目标数据。 |
| 移除关联指针／Provider 记录 | 区分配置记录与程序卸载，不扩大为删除全部第三方工具。 |
| 隔离保留 | 明确告诉用户旧资料仍在，不计为永久删除；不默认隔离整个日常浏览器。 |
| 备份恢复 | 只恢复本次实际备份且可恢复的内容，列明认证等恢复限制。 |

### 9.3 执行一致性

用户确认后，执行清单固定到具体对象和动作。执行前检查对象是否变化、是否仍属于所选环境、是否被占用；原计划失效时暂停对应操作并更新说明。AI 不在执行中新增对象、生成任意删除命令或扩大授权。

需要退出客户端才能完成的操作，应先提示并征得同意，不强杀用户正在进行的项目工作。没有权限或不支持当前对象时记录失败／未完成，不伪装成功。

### 9.4 备份与恢复

配置修改和具有恢复需要的清理应展示备份策略、存放位置和可恢复范围。含身份资料的备份必须在本地受限保存，不进入普通日志、模型输入或公开报告；保留期限与具体保护实现另行确定。

备份本身纳入「旧备份与隔离副本」检测。报告区分「活动路径已清理」与「备份仍保存相关资料」，不能制造已彻底移除的错觉。用户可以单独确认清理备份；永久删除与不可恢复影响必须说明。

恢复只影响本应用此次操作的对象，不重置整台电脑，也不承诺让失效登录在服务端恢复可用。

### 9.5 结果状态

逐项记录：已删除、已修改、已清除记录、已隔离保留、按用户选择保留、原本不存在、未命中、执行失败、未执行／待核验。

复查至少回答：目标处理是否发生；受保护项目内容是否保留；无关账号／站点／配置是否未被波及；是否还有待处理项；评分是否具备更新依据。未命中、原本不存在和历史上删除成功必须保持区别。

### 10.1 页面职责

每项至少包含：问题标识、标题、来源主体、环境／Profile、对象定位、结果分类、严重等级、证据状态、依据摘要、账号关联及用户回答、项目保护标签、推荐动作、操作影响、用户选择、执行结果、复查结果、检查时间和规则版本。

### 10.3 报告导出

支持可读报告与结构化结果导出，供用户留档和后续定位。可读格式与最终字段编码在实现时确定，但至少保留：扫描范围、模式、时间、规则版本、评分依据、问题清单、处理清单、保留项、复查结果与覆盖缺口。

报告明确标注「用户确认账号状态」「本次本地处理结果」，不伪称平台判定、AI 风控探测或整盘无残留。未使用 AI 时显示标准模式来源；AI 中断时显示未完成或降级。

## 12. 验收场景

| 编号 | 场景 | 应达到的结果 |
|---|---|---|
| A01 | 首次打开且已授权 AI | 主入口可直接深度扫描，无聊天框、无技术问卷；执行前没有修改。 |
| A02 | 无模型配置／AI 失败／断网 | 标准扫描、已有报告和本地恢复可用；不假称 AI 已完成。 |
| A03 | 用户回答账号正常 | 对应身份和登录资料保留、不扣分，其他扫描继续。 |
| A04 | 用户回答账号受限 | 明确归属的资料加入推荐清理；最终确认前不删除；不声称解封。 |
| A05 | 用户未回答或归属未知 | 不推断正常或风控，不清理对应身份；关键缺口明确显示。 |
| A06 | 多账号共享浏览器数据 | 不把无法分离的共享数据冒充单账号清理；正常账号影响先说明。 |
| A07 | 项目记录中出现旧邮箱或 org_id | 标记为项目引用并保留，不当作登录凭据删除。 |
| A08 | JSON 混合项目字段和认证字段 | 仅处理已确认字段，项目与其他未授权设置保留。 |
| A09 | 同名文件清后重新生成 | 按当前内容和关联识别新状态，不仅因路径相同判旧残留。 |
| A10 | 针对站点 Cookie／数据库记录清理 | 只处理实际可定位范围；非目标记录保持；原本无记录不记作删除。 |
| A11 | 旧备份含登录资料与项目资料 | 明确活动／归档状态，保护项目内容；备份是否清理由用户确认。 |
| A12 | 同一问题涉及多个文件 | 归并扣分，详情列出所有对象，不重复抬高严重程度。 |
| A13 | 存在危急／重要问题 | 按初始规则扣分且遵守 59／84 上限；正常缓存或项目资料不因存在扣分。 |
| A14 | 关键范围未读到 | 不出最终总分，列明范围与原因；不存在与未访问分开。 |
| A15 | 用户保留已确认问题 | 按用户意愿不处理，但问题与分数不自动清零；误报更正有说明。 |
| A16 | 确认后文件改变或被占用 | 暂停失效操作并说明，不扩大范围、不强杀工作会话。 |
| A17 | 处理部分成功、部分失败 | 分项报告，复查成功项与项目保护结果，不报全部完成。 |
| A18 | 执行后复查 | 删除、修改、隔离、保留、原本不存在分别计数；复查后再调整分数。 |
| A19 | 恢复备份 | 仅恢复选定且支持的内容，说明身份恢复限制；不覆盖无关文件。 |
| A20 | 导出或交给 AI 的资料 | 无 Token、Cookie 值、代理密码、私钥和未授权项目全文。 |
| A21 | 标准与 AI 同案例对照 | 比较识别、归属、推荐粒度、误报与误删建议，不能用文案长度代替质量。 |
| A22 | 历史来源冲突或证据缺口 | 保持批次与来源区分，不将任务名、计划或路径不存在补写成成功删除。 |

尚未约定性能阈值、模型预算与准确率数值，不能自行宣称已达生产指标。上述场景是功能验收要求，不是已跑出的测试报告。

### 13.4 正常基准与社区补充

用户反馈清理后一直使用良好，作为第一版环境经验样本；它不能单独证明每项删除动作都降低了平台风控。历史中保留的 projects、skills、CLAUDE.md 和恢复资料同样是基准的重要部分。[U；S1 §5]

社区线索采用「先纳入检查、再按本机证据分类」的方式。不得把“存在旧会话”“发现 org_id”“曾被社区提及”直接转为危急或必删规则；不得把按邮箱搜索未命中扩展成整盘没有账号残留。[G3；G4]

本文件不复制真实账号邮箱、组织 UUID、账号 UUID、Token、Cookie 值、私钥或个人绝对项目路径。后续发布到 Git 的测试数据应使用脱敏样例。

## 14. 尚未锁定的实现参数与完成定义

### 14.1 不影响本份需求基线的待定项

具体 UI 技术栈、模型提供方、各客户端／浏览器／系统的版本支持矩阵、数据库处理方式、备份保护与保留期限、扫描耗时与 AI 成本预算，以及逐个检测规则的严重度映射，需要在实现和案例测试中确定。

评分框架已确定，40／15／2、轻度上限 10、59／84 封顶为初始讨论参数；它们不是风险统计。后续调整应以真实样例对照和规则版本记录为依据，不以追求更高危急数量为目标。

这些待定项不能被解释成允许重新加入聊天入口、自动风控判断、默许整目录删除或削减项目保护范围。

### 14.2 本板块的完成定义

在已声明支持的范围内，普通用户能够不依赖路径知识完成自动扫描，得到有依据的严格评分与处理建议；用户回答账号正常时登录资料保留，回答受限时对应资料进入推荐清理；所有写入都在用户确认后执行，项目记录、记忆和配置保留；复查、失败说明、备份与恢复记录可追溯。

**本板块最终承诺的是：查清本地对象、给出专业建议、尊重用户决定、准确执行并如实验收。不是通过清理证明账号解封，也不是以删光资料换取满分。**
