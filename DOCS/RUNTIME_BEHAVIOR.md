# 运行、浏览器、应急与恢复行为

> v1.3。Owner 已确认的行为是固定出口故障阻断、手动应急入口、默认浏览器优先、确认后处理。其余以下默认值为 RECOMMENDED 提案，按对应路径实测后确定；本轮不改变任何本机设置。

## 1. 生命周期建议

| 触发 | 建议实际行为 | 如何验证 |
|---|---|---|
| 首次安装/打开 | 先可只读扫描；未确认启用网络前不接管代理。需要网络服务时解释用途并执行一次安装授权 | 原代理/路由未被启动扫描改变 |
| 启用网络 | 显示方案、受保护程序、白名单、常规维护与应急授权；保护先就绪，后接管业务并验证 | UI 区分配置已写、内核已加载、实际验证 |
| 关闭窗口 | 最小化到托盘，当前任务与网络保护继续；首次用一句提示说明 | 窗口关闭后新连接、核心故障保护仍生效 |
| 开机启动 | 安装时不隐式开启；首次启用网络时提供默认勾选且可见的开机保护选项 | 勾选时保护服务先于受管业务放行；未勾选不承诺开机自动受保护 |
| 重启/服务重启 | 加载最后有效且未撤销的方案，保护先行；读取资源及额度有效性，未知不放开代理 | 重启前后 A 绑定、用户额度和保护一致 |
| 睡眠/唤醒 | 暂停期间留缺口；唤醒先检查保护和网络变化，再恢复原方案；执行到期归档/日报一次 | 漏跑不补造历史，跨日/时区变化按 FD-04 |
| 内核异常退出 | 保持系统层保护，显示正在恢复/失败；有限重试，不放开直连 | 故障期间受保护程序新连接仍不能从本地公网出站 |
| 明确退出界面 | 可退出界面但保留网络服务；“停止管理并恢复原网络”作为单独显式操作 | 确认告知 Claude 后续不再受本应用保护；完成前先结束/暂停受保护客户端业务 |
| 软件升级 | 下载可后台完成；涉及内核/服务替换在用户可见维护窗口执行，保护保持，失败回到仍有效版本 | 中断升级不会留下开放路由；不重置配额和备份 |
| 卸载 | 明确展示停止保护、恢复本应用修改、保留/删除本应用数据选项；默认保留报告/恢复材料，项目不动 | 只撤销本应用拥有且未被外部改写的设置；冲突给出具体恢复步骤 |
| 与现有 Clash/代理工具冲突 | 检测后列出冲突和建议，用户确认接管；不默默停止外部软件或导入所有秘密 | 放弃接管时原环境仍可使用 |
| 磁盘不足 | 保护继续；停止新归档/AI 材料写入并提示空间，不删除活动证据“自救” | 报告标记交付失败/缺口，不能伪造完整日志 |

## 2. 应急上网入口

正常时放在网络方案页次级入口，故障时在保护通知中显示“临时上网/联系支持”。

进入流程：用户主动选择 → 展示目的、可用资源、涉及应用/范围 → 确认 → 开启隔离的应急路由 → 验证应急页面可用且 Claude 仍受固定 A/阻断约束 → 显示醒目的临时状态和结束按钮。

建议默认 30 分钟，到期关闭，可由用户主动延长。退出应急不自动宣布主线路已恢复，原方案需重新验证。不能自动切 Global、把 Claude 组增加备用出口、取消受保护进程规则或一键关 TUN。

应急路径优先复用另一款已安装、可准确区分且不与 Claude 受保护进程混用的浏览器及现成路由能力；没有合适浏览器时，再验证现有应用 WebView2 或其他已批准的独立应用/路径。不新增独立浏览器引擎，不承诺按标签页隔离。禁止按所有 msedgewebview2.exe 一概放行而连带其他应用；同一受保护浏览器不改路，Claude 相关目标在应急浏览器中也仍受 A/阻断约束。

P0 对选定应急路径分别验证可用资源、普通批准目标可达、Claude 仍受保护，以及结束后通道关闭和原方案复查。尚无可靠的一般应急路径时，仍应提供专用支持域名的受限访问办法，并明确“仅联系支持可用、普通应急上网未完成”；不能以受限支持站点或不可靠的全浏览器放行关闭一般应急上网验收项。

订阅超额时，普通应急上网仍受该用户额度约束；联系支持可使用显式声明的最小支持域名直连许可或运营方分配的独立有限支持资源。两者选定一项并经 P0 验证。模板必须列明认证、配置、工单与模型服务各自的正常/故障路径，不能故障后临时开未知直连。

## 3. 默认浏览器专用配置

识别默认浏览器 → 确认实际 Profile（仅存在歧义时）→ 采集当前设置 → 页面补测 → 展示建议与影响 → 用户确认 → 应用支持的设置 → 重新打开同一浏览器验证。

首版可直接复用现行“选定浏览器进程跟随 Claude A”规则；默认浏览器如果同时用于日常，上述影响必须出现在确认页。产品不自动改用户默认浏览器，不隐式新建 Profile，不承诺按标签页隔离。

WebRTC、DNS、语言、系统时区等每项都有修改前值、支持版本、修改方法和复查证据。不支持写入某设置时提供该设置页面的明确人工步骤和复查按钮；不把未完成的自动处理显示为成功。不得强制结束所有 Chrome/Edge/Brave 进程来强行修复。

Chrome 136 起默认数据目录远程调试有新增限制，因此真实浏览器页面诊断是正常方案；不能为了 CDP 新建空配置后把结果替换成用户原浏览器。参见 [Chrome 官方说明](https://developer.chrome.com/blog/remote-debugging-port)。

## 4. 文件清理与恢复

默认扫描当前用户的已发现 Claude 相关范围。权限不足、未知格式或占用明确显示，先完成独立可读项目；不自动提权遍历整个磁盘。

清理清单逐项标注：删除文件/删除目录/修改字段/删除记录/站点清理/隔离保留；同一项目不混报。受限账号可推荐清理，但项目三类资料和其他正常账号仍保留。

建议可恢复配置与身份材料备份保留 7 天，使用当前用户受限访问与系统保护；缓存可说明无法恢复，不假造备份。到期只提示用户检查，不在首版新增自动清空备份任务。恢复前预览冲突，只恢复本应用确实修改的内容，不覆盖之后的用户编辑。

浏览器数据库正在占用时提示关闭所选浏览器并重试，不强杀所有浏览器。若同站点登录态无法区分账号，只能以真实站点影响范围重新确认，不能执行原先“仅一个账号”的旧计划。

## 5. 断网与更新

AI 不可用：保留标准扫描和已有事实、已确认确定性执行、本地恢复、保护及标准日报。网络探测失败标缺测。AI 分析恢复后可手动补做，不重写旧报告。

服务端不可达：仍有效的受管配置可继续使用，服务节点的额度控制必须仍在；客户端不能因查不到后台而自行刷新授权。节点自身计量/执行不可用时保护性停止相应代理，不自动直连。

更新建议每日检查、有效配置失败时有限重试。订阅刷新不得改变用户 A、解除保护或覆盖直连白名单。首次安装的登录/配置引导可由用户明确批准的 bootstrap 域名访问，启用保护后按模板路径；不存在“为了连后台先把所有网络直连”的隐式步骤。

## 6. 数值参数来源

应急 30 分钟、备份 7 天、刷新节奏是候选试验参数。与性能、配额口径一起汇总在 [待定决策](OPEN_DECISIONS.md)，按对应路径先记录实际行为和影响，再确定发布值；不按未达建议值自动淘汰成熟组件或强改上游核心。参数调整不能放宽固定 A 故障阻断、服务端用户限额和既有授权范围；不需要为每次同范围维护重新弹窗。当前文档没有证明这些动作已经运行。
