# 网络评分与基础路由实施提案

> v1.3 · RECOMMENDED。对应 FD-02/N01—N34、FD-03/F13—F28。保留 v1.2 候选评分表供样例校准；这些数值不是账号风险概率、已批准生产评分或选型淘汰门槛。

## 1. 网络评分 NET_SCORE_0.1

网络分独立于 FD-01 文件分，不相加，也不平均第三方站点的风险分。先形成有证据的根本问题，再按以下表生成严重度和扣分；AI 解释证据，不临时赋分。

| 根本问题与必要证据 | 建议等级/扣分 | 不能据此触发 |
|---|---|---|
| 实际受保护客户端出站绕过批准 A，含可证实 IPv6/WebRTC 绕行 | 危急 / 60 | 配置疑似不对、未取得结果、仅看到私网地址 |
| 系统保护明确失效且可建立禁止的新连接 | 危急 / 60 | 一次控制接口读取失败、尚未证明保护失效 |
| 固定链持续不可用或明确受管规则冲突，未观察到绕行 | 重要 / 20 | 一次超时或证据不足 |
| DNS 实际出站违反批准路径，且未归并为同一泄漏根因 | 重要 / 20 | 服务地区标签不同、DNS未捕获或正常批准递归行为 |
| 已确认时区/语言/浏览器设置与用户选择方案不一致 | 轻度 / 3；有证据造成核心故障时才考虑重要 | 中文字体、地区标签、硬件特征单独存在 |
| 全链延迟/稳定性持续超出已建立基线 | 轻度 / 3，需足够测量 | 一次 ping、前置测速替代全链、没有基线 |
| 外部 IP 信誉、TLS/指纹特征差异 | 单独解释，不默认扣分 | 不能仅凭供应商评分推断严重故障 |

同一根因跨 IP/DNS/WebRTC/内核多处表现只扣一次，取证据成立的最严重类别。候选总分=max(0,100−唯一根因扣分之和)；有危急最高39，有重要最高79；轻度合计最多扣15。这和文件分40/15/2、59/84封顶不同，不能混用。

关键检查包括：预期 A/B 已由分配确认、实际配置与保护状态可读、选定真实客户端/浏览器路径有证据、适用 DNS/IPv6/WebRTC 路径已测或有明确阻断证据。关键项缺测显示“未完成”，不发布最终总分；已发现危急仍单独显示。

完整度=已完成适用检查数/应完成适用检查数，排除项必须有不适用依据。专项扫描不拿部分结果算完整总分。复查确认关闭问题才更新分数，用户选择保留问题不会自动清除扣分。

P5 校准至少包括：仅信誉标签异常、多个泄漏表现同因、固定链错误但无绕行、DNS缺测、正常身份/字体、修好后保留历史记录。先复用这些代表性样例明确分级与用户解释，再确定发布参数，不另建复杂风险评分平台。规则变更修改 score_version 并跑同一组样例；未校准数值不能倒逼修改成熟网络核心。

“持续不可用”初始建议是在用户主动检测的同一目标上三次请求失败，间隔5秒；不在被动日志任务中造请求。“持续超出基线”建议使用至少20次授权全链测量、比较相同目标/时段的成功率与P95；没有可信基线先只报告数值，不扣分。参数经 P0/P5 实测调整并明示版本。

## 2. 基础路由模板

建议优先顺序：明确的回环/必要建链通信 → Claude 保护域名与进程 → 手动应急独立应用范围 → 当前模式普通业务规则 → 未知代理业务固定出口或拒绝。例外只能覆盖本身所需对象，不能吞掉 Claude 域名与进程保护。

日常建议也以 TUN 统一接管后按白名单直连，减少双接管语义；P0 验证兼容性后固定。专用模式停用日常公网直连条目但保存清单。

默认直连清单由后台维护明确域名预设，经发布审查下发；首个验证模板先为空，从 Owner 当前已批准清单中提取公开域名并确认后补入。不能把个人凭据、组名或整个生产 YAML 复制成公共模板。未下发清单时显示“未设置直连网站”，其余流量走 A，不默默全国内 DIRECT。

批准固定链不支持 UDP 时明确拒绝或采用已验证可行承载，不改走其他出口。IPv6验证接管/拒绝，不默认禁用整机IPv6。DNS/STUN主动测量仅使用批准目标；日常归档不发探测流量。

控制面模板逐项声明登录、配置、模型、配额和工单的正常及故障路径。首次 bootstrap 或手动支持通道须明确启动，只开放批准的最小范围；不能以“控制面”名义放行任意目标。
