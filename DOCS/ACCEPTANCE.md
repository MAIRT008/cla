## 3. 数值与证据

性能、预算、计量单位和故障响应候选见 [待定决策](OPEN_DECISIONS.md)。候选阶段记录实测与用户影响，不把未确认建议数字当作淘汰条件；发布前明确采用值再按其验收。精确清理、固定 A、用户独立停用等既定硬行为不因此放宽，不能用测试脚本悄悄改变商业或功能口径。

每条验收记录：case_id、软件/系统/资源版本、样例或测试资源引用、授权范围、操作、预期、实际、证据路径、状态、缺口。真实环境截图可辅助，不能代替流量结果、文件差异和服务端断流回执。

所有故障注入和文件删改在授权测试环境进行，日常只读审计不触发这些测试。个人历史脚本的八条合成回归只是复用证据，不能填入本表产品 PASS。

## 4. 放行判断

功能内测：首批矩阵上的核心闭环真实可用，残余问题和未支持范围明确。完整 V1 试用：全部适用原 A 场景与 X 场景执行完成，BLOCK/MAJOR 关闭，MINOR/NOTE 记录并说明影响。

已明确后置的隔离/全平台/全部流量应用归属，不作为首版 FAIL 理由；已确认的用户独立硬限额、真实浏览器、精确处理、固定 A 保护不能后置后仍宣称完整首版。

文档交付检查使用 tools/verify_documents.py，其输出独立记录在 [document-validation.json](index/document-validation.json)。文档修订审核另检查六项优化是否一致落地、原 FD 是否保留和未验证状态是否准确；通过只允许把本包作为后续选型验证的当前依据。复用定型需对应真实接入证据，完整产品需上述运行验收。没有产品代码和运行回执时，产品始终 UNVERIFIED。
